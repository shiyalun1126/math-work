## 口径与边界

- 外部验证集：M²E (Wente47 / ModelScope)，CC BY-NC 4.0，非本项目自采数据，指标须与 self_test 分表报告。
- M²E 是多行公式块，不是学生整页解题过程；没有对错/错因标注，不能当批改评测集。
- 只比对行数，不比对行框位置：exact 高不等于每行内容都切对，需配合 --debug 目检。
- 默认纳入含 \t 的竖式对齐块（M²E 中占多数，全跳过会让样本失去代表性），按 align 分层报；--exclude-align 可排除。
- M²E 图多为 70~300 px 的紧凑小图，与整页作业照不是同一分布；这里的数字不能外推成产品对整页作业的切行准确率。
- `page_mode: null` 表示按短边自动判断：短边 ≥400 px 的块走整页模式，此时 `threshold_ratio` / `min_gap_ratio` / `deskew` 对它不生效。

> ⚠️ **结果解读（别把这个数当产品失败，也别当成功）**：`split_page` 的默认参数是为整页作业照调的，而 M²E 是 70~300 px 的紧凑公式块——行距极小、分数上下标跨行、竖式两列、还带横线本线条；对小图做纠偏旋转会把相邻行糊成一行。这个数字说明**切行模块需要小图专用预处理**（放大后再切 / 关闭纠偏 / 更小的行间合并阈值 / 投影谷底递归切单行带），不能外推成产品对整页作业的准确率。产品主场景的指标仍以自采 P0 八页为准。

> ⚠️ **最集中的单一失败**：`606` 块真值 ≥3 行却只切出 1 行（占 30.3%）。机制（读代码可复现，不是猜的）：这些小图行距只有 2~3 px，`min_gap = max(4, ...)` 把相邻行合并成一条带；条带过滤后只剩这一条，`split_tall` 再拿它自己的高度当参照（`h <= 1.6 * median_h` 就不切），**单带场景永远不会触发切分**。这是算法缺陷，不是阈值没调好——调参救不了它，要改的是「一条带怎么估行高」。

## 怎么读这个数

- `exact` 低 + `bias` 为负 → 行间太密被合成一行，`split_tall` 没切开；优先看 `5 行及以上` 那一层。
- `exact` 低 + `bias` 为正 → 墨点/分数/上下标被当独立行；优先看 `1-2 行` 那一层。
- 想确认切的位置对不对，重跑时加 `--debug 20`，看 `reports/line_debug/` 里画框的图。
- 这个数只给「拍照批改」的**切行模块**做外部效度证据，**不替代** `docs/手写数据采集清单.md` 里 P0 八页的伪推导 / 拍摄退化真值。

# 题目归档：按时间收，分两个区

"归档"是 `app.py` 的第五个页签。它记的不是对错，是**你什么时候做了什么**。

## 1. 它和「错题本」不是一回事

两个页签都在收东西，看着重复，其实问的是两个不同的问题：

| | 错题本（`cases.py`） | 归档（`history.py`） |
|---|---|---|
| 回答 | 我缺哪个动作 | 我什么时候做了什么 |
| 收什么 | 只收判错的 | 全部事件（含只看了答案的） |
| 排序 | 按错因的严重程度 | 按时间，新的在上 |
| 读法 | 聚合（"漏解 5 条，占 38%"） | 流水（"11-12 15:41 改了这一页"） |
| 落盘 | `data/cases.jsonl` | `data/history.jsonl` |

一句话：**错题本是复盘用的，归档是翻旧账用的。**

为什么另起一个文件，而不是把 `cases` 改一改：

1. `cases` 只收判错的。搜题看过答案就走的那些题根本不会进去，而归档要收的恰恰包括它们。
2. 聚合视图希望数据越少越好，流水视图一条不能少——两种读法对存储的要求是相反的。
3. `cases` 已经被错题本页签依赖，改它会牵一片，收益不抵风险。

## 2. 两个区，同一份数据

存储只有一份，两种读法：

**区一 · 题目记录**——全部事件，按时间倒序。列是 `时间 / 动作 / 题目 / 结论 / 备注`。

三种动作：

| 动作 | 什么时候写 | 结论列写什么 |
|---|---|---|
| 搜题 | 上传图片识别成功、或贴 LaTeX 求解 | 看过 |
| 批改 | 点「批改」或拍照批改 | 全对 / 部分对 / 有错 / 没读准 |
| 手动标 | 在待检查区手动加一条 | 待查 |

**区二 · 待检查步骤**——把所有记录里的 `pending` 摊平，按时间倒序。列是 `时间 / 题目 / 位置 / 这一步 / 为什么 / 谁标的 / 状态`。

## 3. 待检查区只收「没把握」，不收「判错」

这条是刻意的，也是最容易做错的地方。

判错的行（`verdict == "wrong"`）**不进待检查区**。那是**已经确定的结论**，已经进错题本了；
再塞进待检查区，用户会以为"系统在怀疑自己刚才的判断"，两个区就失去区分度。

收进来的是这三类：

| 来源 | 判据 | 显示的原因 |
|---|---|---|
| 这一行没认出 | `kind == "unparsed"` | 这一行读不出完整式子 |
| 判不出来 | `verdict == "unknown"` | 步骤自带的说明，或"这一步没判出来" |
| 题面读错 | `role == "problem_misread"` | 题面那行读得不对，整页结论不可靠 |

`verdict == "suspect"` 也收——那是"系统本来要判错，但证据不足，主动降级"的情况。
降级这个动作本身就说明没把握，正好是该被看见的信号。

"谁标的"这一列区分 `系统` / `我`：系统标的必须摊到台面上（它从不假装有把握），
自己标的是你主动留的欠账。两者混在一起会分不清"这是它不确定"还是"这是我当时没懂"。

## 4. 四个刻意的决定

**时间存进记录里，不是显示时算的。** `ts` 是写入时刻的完整 ISO 串，界面只截到分钟显示。
如果时间靠文件名或文件修改时间推断，文件一搬、时区一变、异地同步一次，整条时间线就错了。
用户要的"标注时间"是**事件发生的时间**，它必须跟着记录走。

**3 秒内同题同类去重。** 双击按钮会连触发两次，时间线上就是两条一模一样的记录。
窗口不能再长：隔一分钟再看一遍同一道题，那是真有两次，不该合并。

**"已复查"可以撤销。** 一个只会单向推进的状态机，用户不敢点——万一标错了就永远错下去。
所以 `mark_done` 和 `reopen` 是成对的，两个按钮都在界面上。

**写文件先写 `.tmp` 再换过去。** 标"已复查"要重写整个 jsonl（就地改一行做不到）。
中途被打断时，直接覆盖会让归档少一半。`Path.replace` 在同一分区上是原子的。

## 5. 代码位置

| 文件 | 干什么 |
|---|---|
| `mathagent/history.py` | 存、读、两个视图、`pending_from_check` |
| `app.py` | `on_image` / `on_latex` / `on_grade` / `on_photo` 各记一条；「归档」页签 |
| `tests/test_history.py` | 16 项：时间戳、去重、pending 筛选、撤销幂等、半截行容错 |

`_archived()` 把归档调用包起来：**归档失败不吞掉已经算好的结果**。
用户此刻要的是这道题的答案，不是"归档没写进去"。但也不静默——往 stderr 留一行，
下次翻日志能发现少了哪一条。

## 6. 隐私

`data/history.jsonl` 已进 `.gitignore`，并在 `data/assets.csv` 登记为 `text_snapshot`
（`contains_personal=yes`），`tools/check_assets.py` 会逐条 `git check-ignore` 断言它进不了仓库。

它比错题本更敏感一点：错题本记的是"我在哪一步错了"，归档连"**我什么时候搜过哪道题**"
都记下来了。搜题记录本身就是一份学习行为日志。

删归档：直接删 `data/history.jsonl` 即可，没有索引、没有别的文件依赖它。
界面上目前没有"清空"按钮——**删除是不可逆的，这一版先不做**，需要时手动删文件。

## 7. 学生端为什么没接

`app_student.py`（整页批改的极简界面）没有归档页签。那是给中学生用的，
每多一个页签就多一次分心；归档是给"想复盘"的人用的，放在完整版 `app.py` 里。

如果以后要接：`photocheck` 返回的 `PhotoCheck` 里已经有 `lines` 和 `work`，
`history.record_grade(pc.work, source="photo")` 一行就能落一条，`pending_from_check`
会自动把"没认准的行"挑出来。缺的不是代码，是"学生端该不该有历史"这个产品判断。

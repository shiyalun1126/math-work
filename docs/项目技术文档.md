## 1. 项目概述

### 1.1 一句话

给一张手写数学式子的照片，输出可编辑的公式、可信的识别结果、以及分步解答；识别不确定时主动向用户确认，而不是硬猜。

### 1.2 要解决的问题

现有拍题应用（作业帮、小猿搜题一类）采用的是**题库检索优先**的路线：拍照 → 特征匹配题库 → 命中则返回原题解析。这条路线有三个结构性缺陷：

| 缺陷 | 表现 |
|---|---|
| 依赖题库覆盖 | 原题不在库里就退化为通用 OCR，质量断崖 |
| 答非所问 | 返回的是"题库里那道题"的解析，不是"纸上这个式子"的解析 |
| 不可验证 | 识别环节没有置信度，错了也继续往下算，用户看到的是一本正经的错误 |

学生的真实需求往往是**自己写的、错的、或者题库里没有的**式子，这正是检索路线最弱的区间。

### 1.3 定位

不追求"通用解题"，追求**限定域内的可信**：

> 在声明覆盖的题型范围内，系统给出的每个结果都可追溯、可验证；超出能力边界时，系统自己知道并说出来。

这个定位的副产品是三个可量化的指标——语义等价率、人工干预率、干预后准确率——它们是题库路线无法提供的。

### 1.4 范围

| | 一期（必做） | 二期（拓展） |
|---|---|---|
| 题型 | 一元/二次方程、方程组、代数化简、简单求导与积分 | 不等式、数列、解析几何 |
| 输入 | 单行手写公式，拍照（离线图像） | 多行、平板笔迹（在线 stroke） |
| 输出 | LaTeX + 语法树 + 求解结果 + 分步讲解 | 同左 + 图形理解 |
| 图形 | 不做 | 结构化描述 + 重绘比对（限定三角形/圆） |

> **v0.5 的收窄**：先把「方程」这一类单独做成可交付入口 `app_equation.py`
> （题目搜答案 + 过程批改，端口 7861），含参数方程按参数分情形给答案，
> 答案按方程标准形缓存。范围、边界与实测见 `docs/方程题型.md`。
> 代数化简、求导积分仍只在大 MVP（`app.py`）里，没有进这个单题型入口。

### 1.5 明确不做

- 多行对齐排版、矩阵、分段函数、页内图文混排
- 竞赛级难题的完整证明
- 手写体个性化建模（不做用户自适应）

范围声明要写进最终报告，越清晰越显得专业。

### 1.6 任务定义（JTBD）

上面的范围之所以这样划，不是按"技术难度"划的，是按**用户提交的任务**划的。完整分析见 `docs/JTBD.md`，结论有三条：

- "拍照搜题"不是一个任务，是三个可以分别雇佣的任务：**转录**（纸→可用表达式）、**判定**（我对不对/错在第几步）、**讲通**（为什么/下次怎么想）。J1 是前置条件，**J2 是信任枢纽**，J3 是价值兑现。
- 题库路线的产品把资源压在 J1 和 J3，默认 J2 会自然成立。但 J2 有独立的成功判据和最高的失败代价（说"对"而实际错，学生会照抄进作业）。**本项目的工程重心就在 J2。**
- 对齐到 Ulwick 的 Job Map 八步，用户真正反复卡住的是第 4（确认输入对不对）、6（判断输出可不可信）、7（低成本修正）步，而不是第 5 步（执行）。所以本文档后面所有"验算"相关设计，都不是锦上添花，而是产品本体。

判断某个功能该不该做，先问它服务哪条 job；答不上来的，就是堆上去的。

v2（2026-11-12）补了一节现状对账，有两处值得在这里留一句：主任务已从"看一眼这一行"
改成"把这一页逐行判完、并说清哪几行没算数"；而"系统不确定时有没有说出来"（O2）
目前**只有机制、没有度量**——整页批改不落盘，干预率算不出来。要说这条已成立，
得先把判定结果和来源写进 `runs/`。

```
                    │  整页 → 自动切行 → 单行图 + manifest      │
                    └───────────────────┬──────────────────────┘
                                        ▼
                    ┌──────────────────────────────────────────┐
                    │  M2 感知层                                │
                    │  单行图 → LaTeX + 置信度 + 候选集          │
                    └───────────────────┬──────────────────────┘
                                        ▼
                    ┌──────────────────────────────────────────┐
                    │  M3 结构层                                │
                    │  LaTeX → 规范化 → SymPy 表达式 / 语法错误  │
                    └───────────────────┬──────────────────────┘
                                        ▼
                    ┌──────────────────────────────────────────┐
                    │  M4 校验层（核心）                         │
                    │  ① 重渲染结构比对 ② 多解投票 ③ 可解性检验   │
                    └───────┬──────────────────────┬───────────┘
                    低置信  │                      │ 通过
                            ▼                      ▼
              ┌──────────────────────┐  ┌──────────────────────────┐
              │  M6 人工确认          │  │  M5 求解层                │
              │  高亮候选符号让用户点选 │  │  CAS 精确求解 + LLM 讲解  │
              └──────────┬───────────┘  └────────────┬─────────────┘
                         │  回填                     │
                         └──────────► M3 ◄───────────┘
                                        │
                                        ▼
                              ┌──────────────────┐
                              │  M6 结果展示      │
                              │  M7 评测埋点      │
                              └──────────────────┘
```

**贯穿性设计原则**

1. **不确定性必须显式传递。** 每一层都输出置信度，不允许静默丢弃。
2. **算与讲分离。** 数值结果只来自 CAS，LLM 只负责把 CAS 的中间结果翻译成人话。
3. **确定性优先。** 能用规则/符号计算解决的，不交给模型。

### M2 感知层

**职责**：单行图 → LaTeX 字符串 + 置信度 + 候选集。

**输入**：单行小图（灰度/彩色 jpg，宽高比通常 3:1 ~ 8:1）
**输出**：`RecognitionResult`（见 §4.1）

#### 三条可选路线

| 路线 | 做法 | 优点 | 代价 | 用途 |
|---|---|---|---|---|
| A 通用 VLM | Qwen2.5-VL / Qwen3-VL 一类，prompt 要求只输出 LaTeX | 零训练，多模态理解强 | 长公式易漏符号，延迟高 | **一期基线** |
| B 专用模型 | UniMERNet / pix2tex（LaTeX-OCR） | 结构准确率高、快 | 对手写泛化一般，需 GPU | 对照实验 |
| C 微调 | 在 HME100K 子集上 LoRA 微调 A 或 B | 手写域内最佳 | 需要 GPU 与调参时间 | 二期加分项 |

一期先跑 A，用 B 做交叉验证——两者分歧本身就是校验信号。

#### 置信度怎么来（关键设计）

多数 VLM 不返回 token 概率，直接拿 logprob 不现实。改用**采样一致率**：

```
对同一张图采样 k=5 次（temperature 0.7）
→ 每个结果走 M3 规范化成 AST
→ 按语义等价聚类
→ conf = 最大簇大小 / k
→ candidates = 各簇代表 + 簇内占比
```

好处：与 M4 的多解投票复用同一套等价判定，成本只在推理侧。坏处：k 倍延迟，演示时可降到 k=3。

**符号级定位**：把 k 次结果做字符级对齐（编辑距离），把分歧位置映射回图像区域的横向坐标，供 M6 高亮。一期可以先做"整式高亮 + 候选列表"，符号级定位作为二期。

#### 输出规范化

识别结果必须过一遍规范化，否则同一个式子会有十几种写法：

| 处理 | 例子 |
|---|---|
| 去 `\left` / `\right` | `\left(x\right)` → `(x)` |
| 去多余空格与 `{}` | `\frac { a } { b }` → `\frac{a}{b}` |
| 乘号统一 | `\times`、`\cdot` → 视上下文归一 |
| 常见混淆纠正 | `x` / `×`、`1` / `l`、`O` / `0` 按上下文与置信度决定 |

规范化器必须是**可逆可查**的：记录每一次改写，报告中要能说明"这一处是我改的"。

### M3 结构层

**职责**：LaTeX → SymPy 表达式；把语法/语义错误显式暴露出来。

**输入**：LaTeX 字符串
**输出**：`ParsedExpr`（见 §4.2）

#### 实现

```python
from latex2sympy2 import latex2sympy
expr = latex2sympy(latex)          # 失败抛异常
```

`latex2sympy2` 不是万能的，要包一层：

| 异常类型 | 归类 | 处置 |
|---|---|---|
| 括号不配平、非法命令 | `syntax_error` | 直接判废，回 M2 重采样 |
| 解析成功但含未定义符号 | `unknown_symbol` | 视为变量，继续 |
| 关系式含多个 `=` | `unsupported` | 一期不支持，提示用户 |

#### 规范化（语义层）

语法解析成功不等于可比。判等之前必须规范化：

- `x*2` 与 `2*x` → SymPy 自动处理
- `\frac{2x-6}{2}` 与 `x-3` → 用 `simplify(a - b) == 0` 判等，**不做**主动化简（化简会掩盖识别错误）
- 定义域：分式方程必须记录分母不为零的约束，否则 `x=1` 会被误判为合法解

#### 约束解码

若走自研/微调模型，用 `outlines` 或 `XGrammar` 做语法约束，只允许输出合法 LaTeX。对 VLM 路线不适用（无法控制解码），改为**后置过滤**：非法结果直接重采样。

### M4 校验层（核心）

**职责**：判断 M2 的结果可不可信；不可信就交给用户，不硬算。

**输入**：`RecognitionResult` + 原图
**输出**：`VerificationResult`（见 §4.3）

#### 三路校验

**① 重渲染结构比对**

把识别结果用 mathtext 渲染出来，与原图比对。

这里要诚实：**像素级 SSIM 不可用**——渲染字体与原手写字体完全不同，SSIM 会低到没有区分度。改用**结构统计量**：

| 统计量 | 说明 | 判据 |
|---|---|---|
| 横向分块数 | 沿 x 轴投影的分段数，近似符号个数 | 差值 > 30% 判异常 |
| 纵向层次 | 分式/上下标的层数（递归统计 AST 深度） | 深度不符判异常 |
| 包围盒纵横比 | 宽/高 | 比值偏差 > 40% 判异常 |
| 墨迹密度分布 | 按 3×3 网格统计墨迹占比 | 相关性 < 0.5 判异常 |

这套指标很粗糙，但能抓住"少识别了一个分式层"或"漏了一整段"这类严重错误。定位是**粗筛**，不是精判。

**② 多解投票**

复用 M2 的 k 次采样结果，在 AST 上聚类，取最大簇。簇内占比即置信度。

**③ 可解性检验**

| 检查 | 说明 |
|---|---|
| 可解析 | 已由 M3 保证 |
| 未知量数量 | 方程数与未知量数是否匹配（欠定 → 无法唯一求解） |
| 类型可解 | 一期只支持代数方程/简单微积分，其余判 `out_of_scope` |
| 解域 | 分式方程查增根；根号方程查定义域；对数查真数 > 0 |
| 代回验证 | 把解代回原方程，残差应为 0 |

**决策规则**

```python
if conf < TAU_CONF or structure_check_failed:
    return needs_review(candidates)
if not solvable or out_of_scope:
    return out_of_scope(reason)      # 不是失败，是边界声明
return accepted(expr)
```

`TAU_CONF` 初值 0.6，在验证集上标定。**这个阈值本身就是一个可报告的结果**：画出阈值-干预率-准确率曲线，能找到拐点。

#### 与人工确认的边界

只有"能给出 2–5 个具体候选"时才触发人工确认。如果系统完全不知道错在哪，让用户重拍比让用户点选更合适。

### M5 求解层

**职责**：算得对，讲得清。

**输入**：`ParsedExpr`（已通过校验）
**输出**：`SolveResult`（见 §4.4）

#### 分工

| 步骤 | 谁做 | 说明 |
|---|---|---|
| 求解 | SymPy | `solve` / `solveset` / `diff` / `integrate` / `limit` |
| 化简与验算 | SymPy | `simplify`、代回残差 |
| 步骤组织 | 规则 + LLM | 先按题型套模板（移项、配方、求导法则），再让 LLM 补过渡语 |
| 自然语言讲解 | LLM | 输入是**结构化的中间结果**，不是原图 |

LLM 的输入长这样，不是图片：

```json
{
  "goal": "求解一元二次方程",
  "expr": "x**2 - 5*x + 6",
  "steps": [
    {"action": "判别式", "value": "delta = (-5)**2 - 4*1*6 = 1"},
    {"action": "求根公式", "value": "x = (5 ± 1) / 2"},
    {"action": "得到解", "value": "x1 = 3, x2 = 2"}
  ]
}
```

**防幻觉的后置校验**：LLM 输出的每一条含等式的断言，都要重新解析并验证成立（`simplify(lhs - rhs) == 0`）。不成立的条目直接剔除并标记 `dropped_steps`。这一步能把"讲得头头是道但算错了"的段落拦下来。

#### 含参讨论（`params.py`）

除主元（默认 `x`，没有就取次数最高的符号）之外还有字母时，方程就是**含参方程**，答案要分情形。原来的做法是直接 `solve`，等于默认系数非零——`ax²+(a-1)x-1=0` 只给 `x=1` 和 `x=-1/a`，`a=0` 那一支（`x=-1`）悄悄丢了。学生拿到的答案看着对，实际漏了一整类情形。

现在的流程：

1. **按次数分情形**：`A=0` 与 `A≠0`，后者才是二次方程
2. **按判别式分情形**：`Δ>0` / `Δ=0` / `Δ<0`
3. **每一支都要有见证**：给参数找一组真取值，代进去确认这个情形真的存在、解真的成立

```
原方程：ax² + (a-1)x - 1 = 0
判别式：Δ = (a-1)² - 4·a·(-1) = a² + 2a + 1

情形 1：a ≠ 0 且 Δ > 0     x = -1 或 x = 1/a
情形 2：a ≠ 0 且 Δ = 0     x = (1-a)/(2a)
情形 3：a = 0              x = -1
验算：① a=-3  ② a=-1  ③ a=0
```

三处非做不可的细节：

- **见证不能只靠整数取样**。`mx²-3x+2=0` 的 `Δ=0` 只出现在 `m=9/8`，整数和半整数都试不到，那一支会被误判成「不可能」而删掉。所以先把每个等式条件对每个参数解出来，把解填进取值池。
- **不可能的分支要删**。`x²+2x+m=0` 的二次项系数恒为 1，就不存在「`A=0`」这种情形；找不到见证的分支不写进答案。
- **`Δ<0` 叫「无实根」，不叫「无解」**。二次方程没有实根和一次方程 `0·x=c` 无解是两回事，混用会误导。

另外顺手修了一个老毛病：未知数不能取「字母序最小的那个符号」。`x²-2mx+m²-1=0` 原来被解成 `m = x±1`——答的是另一个字母。

## 4. 接口约定

所有模块间传 JSON 可序列化的 dataclass / dict，便于落盘复盘。

### 4.1 RecognitionResult

```json
{
  "latex_raw": "\\frac{2x-6}{2}=6",
  "latex_norm": "\\frac{2x-6}{2}=6",
  "confidence": 0.8,
  "candidates": [
    {"latex": "\\frac{2x-6}{2}=6", "weight": 0.8},
    {"latex": "\\frac{2x-6}{2}=b", "weight": 0.2}
  ],
  "sampler": {"k": 5, "temperature": 0.7, "model": "qwen2.5-vl-7b"},
  "latency_ms": 1840
}
```

### 4.2 ParsedExpr

```json
{
  "latex": "\\frac{2x-6}{2}=6",
  "sympy_str": "Eq((2*x - 6)/2, 6)",
  "kind": "equation",
  "vars": ["x"],
  "constraints": [],
  "status": "ok",
  "error": null
}
```

`status` ∈ {`ok`, `syntax_error`, `unknown_symbol`, `unsupported`}

### 4.3 VerificationResult

```json
{
  "verdict": "review",
  "confidence": 0.6,
  "checks": {
    "structure": {"passed": true, "block_count_diff": 0.1, "depth_match": true},
    "vote": {"passed": false, "top_share": 0.6},
    "solvability": {"passed": true, "reason": null}
  },
  "candidates": ["\\frac{2x-6}{2}=6", "\\frac{2x-6}{2}=b"],
  "reason": "采样结果不一致，建议确认分母后是否为 b"
}
```

`verdict` ∈ {`accept`, `review`, `out_of_scope`}

### 4.4 SolveResult

```json
{
  "solved": true,
  "solutions": ["x = 3"],
  "steps": [
    {"idx": 1, "action": "两边同乘 2", "expr": "2x - 6 = 12"},
    {"idx": 2, "action": "移项", "expr": "2x = 18"},
    {"idx": 3, "action": "两边除以 2", "expr": "x = 9"}
  ],
  "explain": "……",
  "dropped_steps": [],
  "verified": true
}
```

## 6. 评测方案

### 6.1 指标定义

设测试集 N 条，`P_i` 为第 i 条的预测，`G_i` 为标注。

| 指标 | 定义 | 用途 |
|---|---|---|
| **ExpRate** | `(1/N) Σ 1[P_i == G_i]`（字符串完全一致） | 与文献可比的传统指标，偏严格 |
| **语义等价率** | `(1/N) Σ 1[simplify(parse(P_i) - parse(G_i)) == 0]` | 真实可用性，容忍排版差异 |
| **可解率** | 能走到 M5 的样本占比 | 衡量流水线通畅度 |
| **端到端正确率** | 解集与标准解集一致的比例 | 用户视角的最终指标 |
| **人工干预率** | `verdict == review` 的占比 | 系统自知程度，**越低越好但要与准确率同看** |
| **干预后准确率** | 干预后正确数 / 干预样本数 | 交互设计是否有效 |
| **幻觉率** | 被后置校验剔除的步骤数 / 总步骤数 | 讲解可信度 |
| **端到端延迟** | P50 / P95 | 演示体感 |

**为什么不只报 ExpRate**：手写识别里 `\frac{1}{2}x` 和 `\frac{x}{2}` 语义相同但字符串不同，ExpRate 会判错。语义等价率更接近用户感知。两个都报，差值本身是发现。

### 6.2 消融实验矩阵

| 配置 | 感知 | 结构校验 | 多解投票 | 人工确认 | 说明 |
|---|---|---|---|---|---|
| A | VLM 端到端直接解题 | – | – | – | 对照组：直接问模型答案 |
| B | VLM | ✓ | – | – | 加上形式化与可解性检查 |
| C | VLM | ✓ | ✓ | – | 加投票 |
| D | VLM | ✓ | ✓ | ✓ | 完整系统 |
| E | 专用公式 OCR（SimpleTex） | ✓ | ✓ | ✓ | 换感知主干，与通用 VLM 对比 |

**预期结论方向**（写作时的假设，需用数据验证或推翻）：

- A 在简单题上不弱，但复杂结构题准确率骤降，且**幻觉率高**
- B 相对 A 提升主要体现在"识别错了会被发现"，而不是"识别更准"
- C 提升有限（因为 A/B 的单次采样往往已经一致），但在难例上有效
- D 的收益是**人工干预率下降 + 干预后准确率上升**，端到端准确率提升靠用户配合
- E 取决于手写域匹配度，可能反超也可能持平

如果实测推翻了某条假设，那比验证它更有价值——写进报告的"意外发现"一节。

### 6.3 统计处理

测试集仅 105 条，点估计不可靠。所有比例指标附 **bootstrap 95% 置信区间**（重采样 1000 次）。报告里写成 `62.5% [51.3, 73.1]`，不要只写一个数。若只统计其中的难例子集（30 条），区间会更宽，需单独标注样本量。

> **现状核对（2026-11-10，写报告前必读）**：105 条是采集计划的**目标值**，不是已有数据。
> `data/labels.csv` 现有 150 条标注（`self_train` 95 / `self_test` 55），但 `data/raw/`、
> `data/self/`、`data/test/` 全为空，对应照片一张都没拍。本节所有识别类指标在照片落地前
> 都不得报数，也不得把计划值当样本量写进报告。批改链路另有一套**不依赖照片**的文本评测，
> 已跑通，见 `docs/批改链路.md` §11 与 `reports/eval_work.md`。

## 7. 技术选型

### 7.1 结论

**感知层不训练，调用现成模型；把工程预算全部投到校验与交互上。**

理由很硬：手写公式识别是长尾问题，200–1500 条自采数据微调一个 3B 模型，几乎必然过拟合，效果大概率不如"两个成熟模型的交叉验证"。而交叉验证恰好就是 M4 校验层要的东西——**用两个供应商互相校验，等于白拿一套多解投票**。

### 7.2 感知层四个候选

| 方案 | 形态 | 单价 | 质量 | 上手成本 | 结论 |
|---|---|---|---|---|---|
| **SimpleTex 公式 API** | 云端，专做公式 | 轻量 ¥0.04/次、标准 ¥0.05/次；累计赠 1000 / 500 次 | 手写与印刷体都在支持范围内，中文场景调优 | 注册拿 token，10 行代码 | **主通道** |
| **Qwen3-VL-Flash** | 云端，通用 VLM | 输入 ¥0.18/M、输出 ¥1.8/M（一次调用约 ¥0.0005） | 结构理解强，能顺带输出"哪里不确定" | 同上 | **第二通道** |
| Qwen3-VL-Plus | 云端，更强 | 输入 ¥1/M、输出 ¥10/M（约 ¥0.0025/次） | 明显强于 Flash | 同上 | 难例子集专用 |
| **PaddleOCR-VL 0.9B** | 本地，Apache-2.0 | 0 元，BF16 约 2 GB 显存 | 公式 CDM 91.43（OmniDocBench），含手写 | 装依赖约 1 小时 | **离线兜底** |

价格取自 2026-11 阿里云百炼与 SimpleTex 开放平台公告，实际以控制台账单为准。

### 7.3 为什么是这三件套

```
主：SimpleTex          → 专用、便宜、快，识别结果作为第一候选
副：Qwen3-VL-Flash     → 便宜到可以每张图采样 5 次，用来做一致性投票
底：PaddleOCR-VL 本地  → 断网可跑，答辩现场不怕网络抽风
```

- **主副不同源**。一个是专用小模型、一个是通用大模型，错误模式不相关，投票才有意义。同源采样 5 次的一致性远高于两个不同架构，这是投票能起作用的前提。
- **副通道便宜到不用省**。Flash 一次半厘钱，105 条测试 × 5 次采样 × 一整套消融，几块钱跑完，可以反复实验。
- **本地模型是保险，不是主力**。4060 8 GB 跑 0.9B 绰绰有余，但它的强项是整页文档结构，单行手写公式未必超过 SimpleTex。它的价值是"没网也能演示"。

### 7.4 成本核算

| 项 | 估算 | 说明 |
|---|---|---|
| 开发期调试调用 | ¥10–30 | 按 2000–5000 次、含 Plus 难例重跑 |
| 完整评测一轮 | ¥5–10 | 105 条 × 3 方法 × 5 采样 ≈ 1575 次 |
| 本地模型 | ¥0 | 只用电 |
| 微调（可选） | ¥20–30 或 ¥0 | 百炼 LoRA 4B 训练 ¥0.006/千 token，1000 条 × 5 轮 ≈ ¥25；本地 4060 QLoRA 约一个下午 |
| **合计** | **< ¥50** | 不含人力 |

**省钱的关键动作：所有 API 结果落盘缓存。** 以图片内容 hash 为键存 json，评测时只读本地缓存。否则调一次 prompt 就把 1575 次调用重跑一遍，两小时能把额度烧完，而且两次结果不可比（模型侧有随机性）。缓存之后，改评测逻辑完全不花钱，这是能不能做消融实验的分水岭。

### 7.5 其余各层

| 位置 | 选择 | 理由 | 放弃的方案 |
|---|---|---|---|
| 语言 | Python 3.12（`F:/PyCharm/python.exe`） | 生态最全，SymPy 必备 | 系统 python 3.13：装不了包 |
| 结构 | latex2sympy2 + SymPy | 成熟，中学数学够用 | 自写解析器：周期不允许 |
| 约束解码 | 暂不做 | 需要本地推理 + outlines，与 API 路线冲突；用 prompt + 后处理正则替代 | 一期不上 |
| 求解 | SymPy | 精确、可验算 | LLM 直接算：幻觉不可控 |
| 讲解 | LLM + 等式级后置校验 | 语言质量与可验证性兼顾 | 纯模板：生硬 |
| 图像处理 | numpy + Pillow | 切行够用，已实现并实测 | opencv：本任务用不到 |
| 界面 | Gradio（含自定义 HTML 组件挂 MathLive） | 30 行出可用页面 | 前后端分离：工期不够 |
| 存储 | 本地 JSON + CSV | 无并发、无多用户 | 数据库、向量库：纯负担 |

### 7.6 明确放弃

这些在课程周期里投入产出比极低，写进报告比硬做更好：

- **从零训练 CAN / BTTR / 自研 encoder-decoder**：需要 CROHME 级标注量和调参周期，一周只能跑出个位数 ExpRate。
- **全参数微调 7B 以上**：8 GB 显存物理上做不了，租卡的钱不如买 API。
- **Mathpix**：识别质量确实好，但按页计费且贵，课程项目用不上。
- **LangChain / LlamaIndex / 向量数据库**：本项目没有检索需求，引入即负债。
- **Docker / 微服务拆分**：单机单进程足够，拆开只会让答辩现场多一个失败点。

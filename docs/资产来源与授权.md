# 资产来源与授权

仓库里每一张图、每一份含识别文本的快照，都要能回答两个问题：**从哪来的**、
**能不能公开**。这份文档说明怎么登记、怎么检查，以及当前哪些项还欠一个答复。

清单在 [`data/assets.csv`](../data/assets.csv)，机器检查在
[`tools/check_assets.py`](../tools/check_assets.py)。

## 为什么"忽略原图目录"不够

`.gitignore` 里早就写了 `data/raw/`、`data/crops/`、`data/test/`，但拍照链路会把
同一张作业的另一种形态存到别处：

| 形态 | 存在哪 | 能还原出什么 |
|---|---|---|
| 原图 | `data/inbox/`、`data/raw/` | 整页笔迹、纸张、桌面环境 |
| 切行小图 | `data/crops/` | 每一行写了什么 |
| 派生图（拼贴、纠偏候选、切行红框） | `reports/p0_*.jpg` | 八页内容在一张图里 |
| 识别文本快照 | `data/photo_results_v*.jsonl` | 每行的 LaTeX、判定、错因 |

原图被 ignore 了，后三种照样在仓库里。所以判断标准不是"这张图在哪"，
而是"这张图里有没有真人的作业内容"。

## 三条规则

1. **新增图片必须登记**。`tests/test_assets.py::test_every_tracked_asset_is_registered`
   会拿 `git ls-files` 比对清单，漏一条就红。登记支持通配（`data/photo_results_v*.jsonl`），
   以后多生成一个版本不用改表。
2. **运行时产物必须被 ignore**。错题本 `data/cases.jsonl` 每条含题目原文、学生答案、
   错的步骤；漏了它，`git add -A` 一次就把学生作业带进公开仓库。
   `test_runtime_outputs_are_ignored` 逐条查 `git check-ignore`。
3. **`status` 只能由人改**。`pending` 的意思是"已登记、发布权还没确认"。
   `check_assets.py` 默认只警告，`--strict` 才算失败。CI 用的是 strict：
   现在清单里没有 pending，所以 strict 是绿的；等哪天有人往仓库里放了实拍图
   却没核发布权，CI 会红在合并之前，而不是安静地合进去。

   本地调试时不想被拦，去掉 `--strict` 就只看警告：

```bash
F:/PyCharm/python.exe tools/check_assets.py            # 日常：pending 只警告
F:/PyCharm/python.exe tools/check_assets.py --strict    # 与 CI 一致：pending 也算失败
```

## 当前状态（2026-11-12）

已登记 40 条：30 张程序生成的夹具、7 张界面截图、5 张实拍衍生图、
3 组运行时文本（`data/photo_results_v*.jsonl`、`data/cases*.jsonl`、
`data/history.jsonl`）。**没有 pending 项**，`--strict` 是绿的。

三组运行时文本都**不进仓库**，登记在这里只为一件事：断言它们确实被 `git check-ignore`
挡住了。归档（`history.jsonl`）比错题本更敏感一点——它连"你什么时候搜过哪道题"都记下来了。

**5 张实拍衍生图 + `data/photo_results_v*.jsonl`（11 份）已确认可公开**（2026-11-12）：
这批手写是记录人自己与家人写的练手题（`x²-5x+6=0`、`2x-6=12`、`x²=5x` 一类），
不是在校学生的真实作业。目检同时确认图里没有姓名、学号、学校、班级、日期。

这一步必须由人来答：目检只能证明"图里没写着是谁"，不能证明"写的人同意公开"。
所以 `status` 的每一次 `pending → ok` 都要有日期和依据，记在 `note` 里。

以后再遇到需要核实的资产：

- **同意发布**：在 `data/assets.csv` 把那一行 `status` 改成 `ok`，`note` 写清依据和日期。
- **不同意发布**：`git rm --cached` 撤出跟踪（本地文件保留），它们会退回 ignore 状态；
  引用它们的文档改成文字描述。

`data/photo_results_v1..v10.jsonl` 是 11 个历史版本的评测快照，内容高度重复。
既然已确认可公开，暂不做删减——每个版本对应一次采集，删了就没法复核
"当时为什么这么判"。

## 与 §R03 的对应关系

| 验收标准 | 落点 |
|---|---|
| 新增错题不会进入待提交 | `.gitignore` 加 `data/cases.jsonl`、`data/cases*.jsonl`；`test_runtime_outputs_are_ignored` |
| 资产有来源/授权记录 | `data/assets.csv`（40 条，含生成脚本与授权依据）+ `tools/check_assets.py` + 覆盖率测试 |
| 发布物无未授权作业 | 实拍图与识别快照全部有授权记录且 `status=ok`；CI 用 `--strict`，新增未核实资产会在合并前变红 |

# 资产来源与授权

仓库里每一张图、每一份含识别文本的快照，都要能回答两个问题：**从哪来的**、
**能不能公开**。这份文档说明怎么登记、怎么检查，以及当前哪些项还欠一个答复。

清单在 [`data/assets.csv`](../data/assets.csv)，机器检查在
[`tools/check_assets.py`](../tools/check_assets.py)。

## 为什么"忽略原图目录"不够

`.gitignore` 里早就写了 `data/raw/`、`data/crops/`、`data/test/`，但拍照链路会把
同一张作业的另一种形态存到别处：

| 形态 | 存在哪 | 能还原出什么 |
|---|---|---|
| 原图 | `data/inbox/`、`data/raw/` | 整页笔迹、纸张、桌面环境 |
| 切行小图 | `data/crops/` | 每一行写了什么 |
| 派生图（拼贴、纠偏候选、切行红框） | `reports/p0_*.jpg` | 八页内容在一张图里 |
| 识别文本快照 | `data/photo_results_v*.jsonl` | 每行的 LaTeX、判定、错因 |

原图被 ignore 了，后三种照样在仓库里。所以判断标准不是"这张图在哪"，
而是"这张图里有没有真人的作业内容"。

## 三条规则

1. **新增图片必须登记**。`tests/test_assets.py::test_every_tracked_asset_is_registered`
   会拿 `git ls-files` 比对清单，漏一条就红。登记支持通配（`data/photo_results_v*.jsonl`），
   以后多生成一个版本不用改表。
2. **运行时产物必须被 ignore**。错题本 `data/cases.jsonl` 每条含题目原文、学生答案、
   错的步骤；漏了它，`git add -A` 一次就把学生作业带进公开仓库。
   `test_runtime_outputs_are_ignored` 逐条查 `git check-ignore`。
3. **`status` 只能由人改**。`pending` 的意思是"已登记、发布权还没确认"。
   本地跑 `check_assets.py` 只警告，`--strict` 才算失败——交付前用 strict，
   把没核实完的项逼出来。

```bash
F:/PyCharm/python.exe tools/check_assets.py            # 日常：只警告 pending
F:/PyCharm/python.exe tools/check_assets.py --strict    # 交付前：pending 也拦
```

## 当前状态（2026-11-12）

已登记 39 条：30 张程序生成的夹具、7 张界面截图、5 张实拍衍生图、
2 组含识别文本的快照。

**6 项待核实发布权**：

- `reports/p0_contact_sheet.jpg`、`p0_orientation_candidates.jpg`、
  `p0_retake_card.jpg`、`p0_split_check.jpg`、`line_crops_check.png`
- `data/photo_results_v*.jsonl`（11 份，含 P0 八页的识别文本）

**目检结论（2026-11-12）**：五张实拍衍生图里没有姓名、学号、学校、班级、日期等
可识别身份的信息，只有手写算式（`x²-5x+6=0`、`2x-6=12`、`x²=5x` 一类）。
但目检只能证明"图里没写着是谁"，**不能证明发布权**——是不是自己或家人写的、
写的人同不同意公开，只有记录人知道。

两种情况，两种处理：

- **同意发布**：在 `data/assets.csv` 把这 6 行的 `status` 改成 `ok`。
- **不同意发布**：`git rm --cached` 把这几个文件撤出跟踪（本地文件保留），
  它们会退回 ignore 状态；引用它们的文档改成文字描述。

`data/photo_results_v1..v10.jsonl` 是 11 个历史版本的评测快照，内容高度重复。
如果只保留最新一份（`v10`）作为可复算证据，其余撤出跟踪，能减少暴露面，
也不影响 `docs/批改链路.md` 里引用的数字——但每个版本对应一次采集，
删了就没法复核"当时为什么这么判"，所以这件事要连着评测口径一起定。

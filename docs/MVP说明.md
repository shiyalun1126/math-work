# MVP 说明：从图片到答案的可信链路

> 目标不是"识别率最高"，而是**认错的时候系统自己知道**。
> 本 MVP 把这句话做成了可点击的东西。

## 一、现在能跑什么

一条完整的链路已经通了，7 个演示样例全部跑出结果：

```
图片 → 多源识别 → 语义等价聚类 → 投票 → （歧义则追问）→ 解析为语法树 → SymPy 求解 → 逐条验算 → 展示
```

实测输出（`python demo.py`）：

| 样例 | 判定 | 一致度 | 结果 |
|---|---|---|---|
| demo1 一元二次方程 | ok | 100% | x = 2，x = 3 |
| demo2 分式方程 | ok | 100% | x = 7/2 |
| demo3 x 与 × 混淆 | **review** | 50% | 需用户确认 |
| demo4 不定积分 | ok | 100% | (x−1)eˣ + C |
| demo5 方程组 | ok | 67% | x = 2，y = 1 |
| demo6 1 与 l 混淆 | **review** | 50% | 需用户确认 |
| demo7 漏写符号 | ok | 67% | x = 6 |

7 例里 2 例触发人工确认，占比 29%。这不是缺陷，是设计目标：**该问的时候必须问**。

## 二、怎么跑

```bash
# 1. 界面
F:/PyCharm/python.exe app.py          # 打开 http://127.0.0.1:7860

# 2. 命令行跑全部样例（不需要浏览器）
F:/PyCharm/python.exe demo.py
```

无需密钥即可运行：没有配 API 时自动走 `fixtures/demo.json` 里的预置候选（演示模式）。

**接真模型只需要 `.env` 一个文件**（项目根目录，已建好，里面写好了每项去哪申请）：

```ini
SIMPLETEX_TOKEN=        # simpletex.cn → 用户中心 → 用户授权令牌
DASHSCOPE_API_KEY=      # bailian.console.aliyun.com → API-KEY 管理
```

填完在界面上点「测试连接」，或命令行：


同一套代码会自动切换到真 API，图片按内容哈希缓存，重复调试不重复计费。
详细申请步骤、模型替换、报错对照见 `docs/接入大模型.md`。

## 三、模块职责

| 文件 | 职责 | 关键设计 |
|---|---|---|
| `mathagent/perceive.py` | 多源识别 | SimpleTex 与 Qwen3-VL 架构不同，错误模式才不相关，投票才有意义 |
| `mathagent/latex.py` | 归一化 + 解析 | 解析失败返回 `ok=False`，不抛异常——否则"识别错"和"解析器崩"混在一起没法排查 |
| `mathagent/verify.py` | 语义聚类 + 投票 | 判定标准是 `simplify(a-b)==0`，不是字符串相等；化简带 3 秒超时保护（跑在子进程里，到点直接杀掉，见 `批改链路.md` §12） |
| `mathagent/solve.py` | 符号求解 + 步骤验算 | SymPy 算、模板讲；每步带 `check` 模式，事后逐条复算，不过关就丢进 `dropped` |
| `mathagent/pipeline.py` | 编排 | 认得出但解不出 → 自动降级为 review；算错时不生成讲评 |
| `mathagent/explain.py` | 大模型讲评 | 只描述思路，禁写公式；输出后回扫，出现无法验证的等式整段丢弃 |
| `mathagent/config.py` | 配置 | 优先读 `.env`，兼容 `config.json` 与系统环境变量；密钥脱敏展示 |
| `app.py` | 界面 | 歧义时候选项点一下即重算，不需重新识别；内含密钥面板与连通性自检 |
| `mathagent/cache.py` | 结果落盘 | 按图片 SHA256 + 参数缓存，改评测逻辑不重复花钱 |

## 四、四个值得看的设计

**1. 步骤是可验算的，不是文案。**
每条 `Step` 带 `lhs/rhs` 和 `check` 三种模式：

- `identity`：声明恒等，验 `simplify(lhs-rhs)==0`（用于"验算（求导还原）"、"代回验证"）
- `equiv`：声明与上一步同解，验解集相同（用于"移项整理"）
- `none`：定义式或结论，不验

积分那条最能说明问题：`∫xeˣdx` 算出 `(x−1)eˣ` 之后，系统会**再求一次导**确认能还原成 `xeˣ`，才把这一步留在界面上。

**2. 歧义不猜，交回给你。**
demo3 里 Qwen 把 `x` 认成了 `×`，得到的 `\times^2-3x+2=0` 解析失败。系统没有静默丢掉它，而是：

- 横幅变琥珀色：「存在歧义，请确认后继续」
- 列出理由：「qwen3-vl 的结果无法解析，已排除」「唯一可用候选没有旁证，建议人工确认」
- 候选区把两条都摆出来，无法解析的那条标了「无法解析」

用户可以点另一条，也可以直接改文本框，回车立刻重算。

**3. 增根会被剔除。**
`(x+1)/(x-2)=3` 解得 `x=7/2`，代回分母 `x-2≠0` 通过。若解出 `x=2`，系统会把它标成「增根已剔除」而不是当成答案。

**4. 讲评也被验算。**
大模型只拿到"已经算对的步骤"和"已经给出的答案"，被要求只讲思路、不准写公式。输出后系统回扫一遍：只要出现一个无法在步骤里找到出处、且两边不恒等的等式，整段讲评作废，界面显示「讲评未生成：……」。

理由很直白——算错的时候讲得越顺，害处越大。所以 `sr.ok=False` 时根本不生成讲评。

## 五、上传真实手写照片

界面左侧「题目图片」可以直接传手机拍的照片，支持三种输入：

| 输入 | 处理 | 结果 |
|---|---|---|
| 单行公式（裁好的小图） | 自动摆正 → 裁到墨迹 → 放大到 640px | 直接识别 |
| 手机拍的整页照 | 会给出黄色提示，告诉你这图里有约 N 行 | 建议先切行 |
| 拖进来的截图 | 同单行 | 直接识别 |

整页照为什么要先切行：

```bash
F:/PyCharm/python.exe tools/split_page.py 我的照片.jpg --out data/crops --debug
```

出来 `我的照片_01.jpg`…`我的照片_10.jpg`，每张是一行，再逐张传进界面即可。

两个自动做的预处理，容易被忽略但影响很大：

- **EXIF 摆正**：手机照片常靠 EXIF 标记方向，不读它就会横着送进模型
- **裁到墨迹**：整页照四周几十毫米白纸，不裁会把这些空白一起编码，等于白白拉低有效分辨率

没有真照片时，可以先用模拟图压测预处理：

```bash
F:/PyCharm/python.exe tools/make_photo_sample.py
```

它把干净式子渲染成"手机拍的"样子——倾斜、侧光渐变、噪点、JPEG 压缩，
四个等级从清晰到很糊。四张全部识别正确，说明裁边和缩放在退化条件下仍然站得住。
但它只是印刷体，**不能替代真实手写**，字迹分布这一层它模拟不了。

## 六、还没做的

诚实列清楚，避免误判进度：

- **演示数据是合成图**，不是真实手写。它们只用来验证链路，不能用来报识别率
- **单源时无法交叉验证**：只配一把钥匙时，一致度是同一模型的自一致性，上限压到 80%。要拿到真正的旁证，必须再配一个厂商的识别模型
- **没有做置信度 token 概率**，用多源投票替代
- **几何图形走的是另一条链路**：`geoagent/` 已有题干+图形的结构 → 校验 → 求解/推理，
  离线测试在 `tests/test_geo*.py`；它**不在本文件的图片→公式链路上**，读图仍依赖外部 VLM
- **识别链路的评测还没跑起来**：`eval/` 已经建好，批改评测跑通了
  （`eval/work_cases.jsonl` 40 条文本过程 + 9 条拍照撤回，见 `docs/批改链路.md` §11），
  但 ExpRate / 语义等价率这些**识别**指标仍然卡在真实手写照片上——`data/test/` 为空，
  一张都没拍，不能报数
- 分式方程、无理方程、含参方程只做了基本处理，复杂情况会落到"解不出"并降级为 review

## 4. 验收与解压（最容易踩 LFS 指针的坑）

```bash
F:/PyCharm/python.exe tools/fetch_m2e.py verify --require-images

# 推荐：只解压评测用得上的图（图包里近 10 万张，全解压又慢又占盘）
F:/PyCharm/python.exe tools/fetch_m2e.py unzip --only-blocks data/public/m2e/blocks.jsonl
# 想全解压：去掉 --only-blocks 即可
```

⚠️ `--only-blocks` 依赖 §5 生成的 `blocks.jsonl`，而**导入只读 jsonl、不需要图片**，
所以实际执行顺序是：**§3 下载 → §5 导入 → §4 解压 → §6 评测**（§9 速查已按此顺序排好）。

`verify` 会检查四件事，任何一件不过都会列进 `problems` 并返回非零退出码：

| 检查 | 为什么 |
|---|---|
| 5 个标注文件在不在、体积够不够 | 防止下到截断文件 |
| 三个 jsonl 每行能否解析、有无 `tex` / `name` | 导入前先知道坏行有多少 |
| `images.zip` 开头是不是 `PK` | **没装 git-lfs 时会下到 130 字节的指针文本**，看着像文件其实没图 |
| zip 里图片数量、与标注 `name` 的对齐率 | 名字对不上，评测会静默少样本 |

`unzip` 把 zip 内多层目录的图片**按 basename 摊平**到 `data/public/m2e_raw/images/`，
并打印 `matched / reference_names`。**对齐率低于 90% 要停下来看**：
说明 zip 里的命名规则和 jsonl 的 `name` 不是一套（例如带 split 前缀），
这时先别跑评测，改 `eval/run_line_eval.py` 的 `index_images` 匹配规则，
否则指标会因为「找不到图」被悄悄削掉样本——脚本会在报告里披露缺图数，但数字已经不可用了。

想先只导一部分试试：`F:/PyCharm/python.exe tools/fetch_m2e.py unzip --limit 500`。

```bash

F:/PyCharm/python.exe tools/import_public.py m2e --src data/public/m2e_raw --limit 2000
```

- `lines.csv`：逐行 LaTeX
- `SOURCE.json`：出处与 **CC BY-NC 4.0** 许可记录

切行评测只看行数，根本不需要它。含 `\t` 的竖式块会被标 `has_align`，评测默认跳过并单列数量。

## 6. 跑切行评测（这一步以前是空的，现在补上了）

```bash
# 6.1 baseline：默认参数，一个字都不调，最诚实
F:/PyCharm/python.exe eval/run_line_eval.py --split test --limit 500 --tag baseline

# 6.2 只在 train 上扫参数网格（含 deskew 开关），结果写 reports/line_params.json
F:/PyCharm/python.exe eval/run_line_eval.py --split train --tune --tune-limit 120 --limit 150 --tag tune

# 6.3 用选好的参数，在没碰过的 test 上报最终数字
F:/PyCharm/python.exe eval/run_line_eval.py --split test --params reports/line_params.json --limit 500

# 可选：导出 20 张画框图，肉眼确认切的位置对不对
F:/PyCharm/python.exe eval/run_line_eval.py --split test --debug 20
```

**参数纪律是脚本强制的**：`--tune` 配 `--split test/val` 会直接报错退出。
在 test 上边调边报，那个 100% 只是拟合出来的，不能写进任何报告。
`--tag` 给报告加后缀，三份报告互不覆盖：`eval_lines_baseline.md`、`eval_lines_tune.md`
（**train 调参数字，不可引用**）、`eval_lines.md`（最终）。
`--smoke` 写 `_smoke_` 前缀，不污染正式报告。

**默认纳入含 `\t` 的竖式对齐块并分层报告**：实测 M²E 里这类块占多数，
早期版本默认跳过会砍掉 70% 样本、让指标失去代表性；`--exclude-align` 才排除。

输出指标包括：行数完全一致 `exact`（bootstrap 95% CI）、误差 ≤1 行、MAE、bias、
过切率、欠切率、按真值行数分层、按是否竖式对齐分层。

怎么读：

- `bias` 明显为负、`5 行及以上` 那层差 → 行间太密被合成一行，`split_tall` 没切开；
- `bias` 明显为正、`1-2 行` 那层差 → 墨点 / 分数 / 上下标被当独立行；
- 两种都看 `--debug` 导出的 `reports/line_debug/*.jpg`，框画在纠偏后的整页图上。

**2026-11-11 实测诊断**（拿 20 张真图逐张看过）：图只有 69×89~309×222 px，
三行公式的行距不到几像素，还带分数上下标、竖式两列、横线本线条；
`estimate_skew` 对小图做旋转会把相邻行糊成一行——同一批 20 块，
`deskew=True` 只对 2 块，`deskew=False` 对 5 块。所以参数网格里必须含 `deskew`。
这不是产品对整页作业照的表现，别拿这个数去说拍照批改不行。

## 7. 报告里怎么写（口径）

可以直接抄的写法：

> 为验证切行模块在真实拍摄版式上的表现，另取外部验证集 M²E（ACM MM 2023，CC BY-NC 4.0）
> 的 `test` 分片 N 个多行公式块，以标注 `tex` 的 `\n` 行数作为真值，
> 报告行数完全一致率 X% [95% CI …] 与平均绝对行数误差 Y。切行参数在 `train` 分片上选取，
> 未在 `test` 上调优。该指标仅反映行数一致性，M²E 未提供逐行 bbox 与错因标注，
> 故不与自采 `self_test` 指标合并，也不用于评价批改结论。

不能写的写法：

- ❌「我们采集了 N 条手写数据」——这是公开数据集，要写「外部验证集」；
- ❌「切行准确率 100%」——只比了行数，没比位置；
- ❌ 把外部集数字和 `self_test` 放进同一张表求平均；
- ❌ 商用场景直接引用——`CC BY-NC 4.0` 需另获授权，且要署名。

引用：Peng, Jin, He. *Read Ten Lines at One Glance*, ACM MM 2023；
数据集 <https://www.modelscope.cn/datasets/Wente47/M2E>。

### 7.1 本次实测结果（2026-11-11，可直接引用）

| 配置 | split | 样本 | 行数完全一致 exact | MAE | bias |
|---|---|---|---|---|---|
| 默认参数 baseline | test | 500 | **13.4% [10.6, 16.4]** | 2.456 | −1.816 |
| train 网格调参 | train | 120 | 26.7%（选参数用，不可引用） | 1.692 | — |
| 调参后在 test 报数 | test | 500 | **24.4% [20.6, 28.0]** | 1.802 | −1.146 |

最优参数：`deskew=false, threshold_ratio=0.03, min_gap_ratio=0.004, min_height=6`
（前四名只差 `min_gap` / `min_height`，**真正起作用的是关掉纠偏**）。
调参带来 +11.0 pp，两区间不重叠，但绝对值仍低：欠切率 60%、`5 行及以上` 仅 9.3%、
竖式对齐块 20.0% vs 普通块 39.1%。

**结论**：现有 `split_page` 是为整页作业照设计的，对紧凑公式块不适用；
这份数据的作用从「拿一个好看的外部数字」变成「量化暴露泛化差距」。
要支持这类图，得做小图专用预处理（放大 2~3 倍再切、关纠偏、更小的行合并阈值、
对单个高行带按投影谷底递归切）。**产品主场景指标仍以自采 P0 八页为准。**

结果偏低时可以这样写：

> 在外部验证集 M²E 的 500 个紧凑多行公式块上，为整页作业照设计的切行参数
> 行数完全一致率仅 13.4% [10.6, 16.4]；在 train 分片选参后提升至 24.4% [20.6, 28.0]。
> 该结果说明切行模块对紧凑小图存在明显泛化差距，主要失效模式是行间粘连（欠切率 60%），
> 需引入小图专用预处理。由于图像分布不同，此指标不用于评价整页作业照的切行表现。

## 8. 失败排查

| 现象 | 原因 / 处理 |
|---|---|
| `check` 报 `token_ready: false` | `.env` 没写、键名拼错或值带多余引号；键名必须是 `MODELSCOPE_SDK_TOKEN`，写完保存再跑 `check` |
| `当前操作需要登录` | 令牌没设、设错窗口或过期；重设 `MODELSCOPE_SDK_TOKEN` 再 `--exec` |
| `找不到 modelscope 命令` | 没装 SDK，或装了不在 PATH；用 `--cli "F:/PyCharm/Scripts/modelscope.exe"` |
| `login 子命令不可用` | 旧版 SDK 没有 `login`；脚本会自动退回 `download --token`（明文不打印、只进进程参数），或升级 `pip install -U modelscope` |
| `images.zip 是 Git LFS 指针` | 走了 git clone 但没装 git-lfs；**改用本脚本的 CLI 下载**，别手动 clone |
| zip 只有几百字节 / `不是有效 ZIP` | 下载被截断或代理返回了错误页；删掉 `images.zip` 重跑 `images --exec` |
| `verify` 说 jsonl 体积不够 | 同上，删掉对应文件重下 |
| 评测 `评测 0 块` | 图片目录不对（`--images`）或名字对不上；先看 §4 的对齐率 |
| 报告里 `missing` 很多 | 同上；脚本已把缺图样本剔除并披露，但样本量不足时不要引用 CI |
| `match_rate < 0.9` | zip 命名规则与 `name` 不一致，先修匹配再评测 |
| 磁盘不足 / 下载极慢 | 图包 543 MB + 解压约 600 MB；换 `--root` 到大盘，或先 `--limit` 只导一批 |
| 报 `--tune` 与 `--split test` 冲突 | 这是故意的，按 §6 的顺序来 |
| 想跳过图片只看格式 | 只跑 §3.1 的小文件 + `probe m2e`，不用下图包 |

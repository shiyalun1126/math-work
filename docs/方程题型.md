# 方程题型：把一个题型做透（v0.5）

> 先把一个题型做到能交付，再谈覆盖多少题型。
> 这一版只做方程：题目进 → 答案出；过程进 → 判定出。

入口：

```bash
F:/PyCharm/python.exe app_equation.py      # http://127.0.0.1:7861
```

`app.py` 那个大而全的 MVP 不动，这一版是独立的单题型入口——范围写在界面上，
用户第一眼就知道它能干什么、不能干什么。

---

## 1. 范围

| 档位 | 题型 | 界面说法 |
|---|---|---|
| **包票** | 一元一次方程、一元二次方程、二元/三元一次方程组 | 覆盖范围内 |
| **能答但要交代** | 含参数方程（按参数分情形）、分式方程（自动验增根）、无理方程（验根）、恒等式、无解方程 | 能答，但要交代边界 |
| **不接** | 三次及以上、三角/指数/对数、非线性方程组、不等式、几何 | 不在覆盖范围内 |

**为什么按这个划。** 判"这一步不成立"要给出反例，反例要求解集可算、可比。
范围划不清最典型的坏结果是：三次方程照算，`x³-1=0` 的复数根被当成答案端给初中生；
或者拿"和我算的不一样"去冤枉一个用配方法的学生。所以出了范围就不给结论，
连"参考答案"都不给——因为"算得出"一定会被读成"这个题型我支持"。

判定不调模型，纯符号：`classify()` 看化简后的次数、分母有没有未知数、是不是恒等。

**谁是未知数、谁是参数**：只有一个 `x/y/z` 时它是主元，其余符号按参数看
（这正是中学「关于 x 的方程，a 是参数」的写法）。`x²+y²=1` 不走这条——
x、y 都在，那是圆的方程，不是含参方程。

## 2. 两条路

### 2.1 搜答案（题目 → 答案）

```
题目照片 ──识别──┐
                ├─→ 抽方程 ─→ 判类型/范围 ─→ CAS 求解 ─→ 答案 + 逐根代回验算
题干文字 ────────┘                    │
                                      └─ 通篇叙述、没有等号 → 模型列方程（只列不解）
```

- **抽方程靠规则，不靠模型。** 学生抄的题九成是「解方程：」加一条式子。
  把中文和中文标点当分隔符切掉，剩下的数学片段里挑含 `=` 的——这一步不能交给模型，
  否则每次结果都可能不一样，而且失败时说不出为什么。
  实测覆盖：`解方程：`、`解下列方程：`、`求方程 … 的解`、`\text{解方程：}`。
- **只有应用题才请模型列式**，而且它**只准输出方程**：求解、验算、答案全部由 CAS 给。
  模型列错，最多是列式错，界面上会标"方程是模型从题面转写的，请核对"；
  模型不可能"讲"出一个答案来。
- **每条根都代回原式验算**，`x = 4 代回原式：15 = 15 ✓` 直接摆在答案下面。

### 2.2 批改（过程 → 判定）

直接复用已有的 `photocheck.check()`（拍照）/ `workcheck.grade()`（文字），
这一版只加一件事：**题面先过一个范围判定**。题面出了方程范围（比如 `x^3-1=0`），
结果卡片上会挂一条黄条——"逐行只做过程内部一致性检查，别把它当最终判定"。

判定口径没有变，仍然是局部有效性：这一步能不能从上一步通过一个合法变换得到。
所以一题多解不会被判错，和你算得不一样不等于你错了。

**方程组是例外，它不能按"相邻两步"判。** 单方程是一条递推链，方程组是一个**条件集**：
`x+y=5` 和 `x-y=1` 是并列的题给条件，谁也不是从谁推出来的。拿递推去判，
第二行会被判"对不上上一步"，一份完全正确的解答判成全错——越是老实抄题的学生越容易中。

所以 `workcheck._grade_linear_system()` 另走一条路：维护一个已知条件集，每多一行就联立一次，
看解集怎么变：

| 联立后的解集 | 判定 | 说法 |
|---|---|---|
| 没变 | ✓ 成立 | 消元/移项/同乘；本来就是题面的等式则说"照抄，不是推导" |
| 变小且非空、仍在开头 | ✓ 条件 | 题给条件，与上一行并列 |
| 变小且非空、已进推导区 | ✗ 丢解 | 比前面的条件更严，会丢掉前面成立的解 |
| 空集 | ✗ 不成立 | 与前面的条件联立后无解 |

判据是**联立后的解集**，不是两行各自长什么样，所以谁先谁后、怎么变形都不影响。
答案核验也换成"代回原题条件"——不能用扩充过的条件集，否则学生自己写的答案代回去当然成立。
题面本身矛盾（`x+y=1` 与 `x+y=3`）时结论是 `gap`：不给对错，先说题目可能抄错了。

进这条路径的门槛是"两个未知数以上且全是一次"。一元二次（含参也算多项）不进来——
它的相邻两步就是等价变形，用递推判得挺准。

## 3. 六个关键决定

1. **模型只列式，不求解。** 答案必须有出处：CAS 算的、能代回验算的。
   少了这条，"搜答案"和"猜答案"就没区别。
2. **恒等式不是无解。** 学生写 `2(x-3)=2x-6` 是同解变形，旧逻辑走 `solve()` 返回空解集，
   判成"未求出解"。这一版在 `solve._solve_equation()` 里先判 `simplify(expr)==0`，
   返回"x 取任意实数"，并在批改表里正常通过。
3. **解集为空是结论，不是失败。** `1/(x-2)=0` 是真的无解，界面必须说"无解"，
   不能说"我没算出来"——后者会让用户去改一个本来没错的方程。
4. **增根必剔。** `(x²-1)/(x-1)=0` 解出 ±1，x=1 让分母为 0，只留 x=-1，
   剔除记录在答案下方明写。
5. **含参答案是一张表，不是一句话；而且每一支都要有见证值。**
   `ax=2` 的答案是"① a≠0: x=2/a；② a=0: 无解"两行，不是 `x=2/a`。
   `params.discuss()` 会给每一支找一组**真实参数取值**代回验算，找不到取值的分支
   直接删掉——「a=0 时方程还是二次」这种不存在的情形不会出现在答案里。
   界面上强制一支一行：压成一行最容易漏看的，正是被压掉的那一支。
   反过来，解里带参数但不用分情形时（`x²-2mx+m²-1=0` 直接就是 `x=m±1`），
   徽章会改口说"不需要分情形"，不写空话。
6. **答案缓存按方程的标准形，不按题面文字。** `x^2-5x+6=0` 和 `x^{2} - 5x + 6 = 0`
   是同一道题，键取 `ParsedExpr.sympy_str`；讲评是否生成也进键（没讲评的那份不能顶替有讲评的）。
   缓存只存算成功的，**算不出来的一律不存**——否则以后判据修好了还会拿到旧的"不给"。
   键里带版本号（`CACHE_VERSION`），改算法必须升版本，不然会拿上一版算法的结论回答新问题。
   命中时界面上明写"命中答案缓存"，不假装刚算过。

## 4. 实测（本机真实运行）

搜答案：

| 输入 | 抽出 | 判定 | 输出 |
|---|---|---|---|
| `x^2-5x+6=0` | 同 | 一元二次 · 覆盖 | `x = 2，x = 3`，两根各代回 `0 = 0 ✓` |
| `解方程：3x+6=15` | `3x+6=15` | 一元一次 · 覆盖 | `x = 3` |
| `解下列方程：x^2=2x` | `x^2=2x` | 一元二次 · 覆盖 | `x = 0，x = 2` |
| `求方程 2x-6=12 的解` | `2x-6=12` | 一元一次 · 覆盖 | `x = 9` |
| `x+y=3, x-y=1` | 同（识别为方程组） | 二元一次方程组 · 覆盖 | `x = 2，y = 1` |
| `x+y+z=6, x-y+z=2, 2x+y-z=1` | 同 | 三元一次方程组 · 覆盖 | `x = 1，y = 2，z = 3`，步骤走消元法 |
| `x^2+1=0` | 同 | 一元二次 · 覆盖 | `无实根`（Δ<0，不给复数） |
| `(x^2-1)/(x-1)=0` | 同 | 分式方程 · 边界 | `x = -1`，剔除增根 `1` |
| `1/(x-2)=0` | 同 | 无解方程 · 边界 | `无解（解集为空）` |
| `2(x-3)=2x-6` | 同 | 恒等式 · 边界 | `x 取任意实数` |
| `x+y=3` | 同 | 二元一次关系式 · 边界 | `x = 3 - y`，明说"解不唯一" |
| `ax=2` | 同 | 含参数 · 边界 | 两支：`a≠0 → x=2/a`；`a=0 → 无解` |
| `(a-1)x=1` | 同 | 含参数 · 边界 | 两支：`a≠1 → x=1/(a-1)`；`a=1 → 无解` |
| `mx^2+2x+1=0` | 同 | 含参数 · 边界 | 四支：Δ>0 / Δ=0 / Δ<0 / `m=0`，各带见证值 |
| `x^2-2mx+m^2-1=0` | 同 | 含参数 · 边界 | `x = m-1，x = m+1`，标"不需要分情形" |
| `x^3-1=0` | 同 | 三次方程 · **不接** | 拒绝，一个根都不给 |
| `小明买3支笔共花18元，每支笔多少元？` | 模型列式 `3x = 18` | 一元一次 · 覆盖 | `x = 6`，代回 `18 = 18 ✓`，标注"方程由模型转写" |
| 题目照片 `fixtures/demo1.png` | `x^{2} - 5x + 6 = 0` | 双源一致 1.00 | `x = 2，x = 3` |

批改（同一道题三种写法）：

| 过程 | 判定 |
|---|---|
| `x²-5x+6=0 / x²-6=5x / x²-5x=6 / x=2 或 x=3` | **伪推导**：第 2 步反例"取 x=2：上一步两边相减为 0，这一步却是 -12 ≠ 0" |
| `x²-5x+6=0 / (x-2)(x-3)=0 / x=2` | **漏解**：过程成立，少一个根 |
| `x²-5x+6=0 / (x-2)(x-3)=0 / x=2 或 x=3` | **成立** |

全量测试 **207 passed**，其中 `tests/test_equations.py` 34 项（抽题 5、范围 8、答题 6、
应用题列式 4、含参数 5、缓存 3、恒等式/无解 3）。

## 5. 代码地图

| 文件 | 职责 |
|---|---|
| `mathagent/equations.py` | 题型内核：`extract()` 抽题、`classify()` 判范围、`answer()` 搜答案、`setup_equation()` 应用题列式、`_ANSWER_CACHE` 答案缓存 |
| `app_equation.py` | 单题型界面（端口 7861），两个页签：搜答案 / 批改过程 |
| `mathagent/params.py` | 含参分类讨论（未改，界面接上了 `discuss()` 的分支答案） |
| `mathagent/solve.py` | 改了一处：恒等式分支（`simplify(expr)==0` → 解集为全体实数） |
| `mathagent/photocheck.py` / `workcheck.py` | 批改链路，未改，直接复用 |
| `tests/test_equations.py` | 34 项回归 |

缓存落在 `.cache/equation_answer/`（子目录名 `equation_answer`），和 API 缓存分开：
删掉它只是下次重算，不会影响识别结果。

接口都是纯函数式，不依赖界面：

```python
from mathagent import equations

a = equations.answer("解方程：x^2-5x+6=0")
a.answer_latex      # 'x = 2，x = 3'
a.checks            # ['x = 2 代回原式：0 = 0 ✓', 'x = 3 代回原式：0 = 0 ✓']
a.topic.coverage    # 'in'
a.cached            # 第二次调用为 True

p = equations.answer("mx^2+2x+1=0")
p.branches          # ['① m ≠ 0 且 Δ > 0: ...', '② ...', '③ ...', '④ m = 0: x = -1/2']

ans, meta = equations.answer_image("path/to/problem.jpg")   # 照片走这条
```

## 6. 还没做

- **一页多题**：切行按行带切，一页两题会把两题的行混在一起（B 集 W20 已记为已知局限）。
- **批改侧的含参**：搜答案已经按情形讨论，批改那边遇到 `ax=2` 仍是逐行判局部有效性，
  不会去核"学生有没有漏掉 a=0 那一支"。要做这一条得先定"漏支"的反例怎么给。
- **图形题、不等式**：明确不做，理由见 §1。

# 手写数据采集清单：要拍什么、拍多少、怎么命名

版本 v1 · 2026-11-10 · 给采集者看的唯一入口

---

## 0. 一句话结论

要拍的是**两套目的完全不同的数据**，别混在一起：

| | 数据集 A · 单行公式 | 数据集 B · 整页解题过程 |
|---|---|---|
| 拍什么 | 一页 10 行互不相干的公式 | 一页**一道题**的完整推导，4~6 行 |
| 喂给谁 | 识别 → 求解链路 | 切行 → 逐行识别 → **批改引擎** |
| 支撑什么指标 | 技术文档 §6 的 ExpRate / 语义等价率 / 干预率 / 消融 A–E | 批改结论、伪推导召回、冤枉率、错因、拍照撤回 |
| 清单 | `data/shotlist.csv` + `data/pages.csv`（**已有，不用重设计**） | `data/work_shotlist.csv`（**本轮新建**） |
| 规模 | 20 页 / 200 条 | 20 页 / 20 道题 |
| 现状 | 清单齐、照片 0 张 | 清单齐、照片 0 张 |

**如果只能拍一批，先拍 B 的 P0 8 页。** 理由很直接：项目现在的独特能力是"能证明你这一步错了"，
而 A 支撑的全是原来的单行识别能力。只补 A，等于给旧能力补证据，新能力在真实手写上仍然零证据；
`reports/eval_work.md` 里那个 100% 是构造文本跑出来的，报告里已经写明不能当能力证明。

**最小可答辩集 = A 的 page_13~15（3 页）+ B 的 P0（8 页）= 11 页 A4。**
完整版 40 页。全拍 A 的 20 页其实比挑着拍更省事——见 §3 的分布说明。

## 1. 数据集 A：题型已经定好，不用再想

`data/shotlist.csv` 200 条，7 类，按页排好序，**照着写就行**：

| 题型 | 条数 | 考什么 | 备注 |
|---|---:|---|---|
| 方程 | 30 | 一元一次 / 二次、括号、分母 | 最基础，识别基线 |
| 方程组 | 10 | `\begin{cases}` 大括号、两行结构 | 单行写不下时按 display 的 `{..., ...}` 写 |
| 化简 | 25 | 分式约分、平方差、因式分解 | 有上下结构，注意留行距 |
| 求导积分 | 25 | `d/dx`、上下限、`lim`、上下标 | 上标位置最容易认错 |
| 复合结构 | 30 | 根号套分式、分数套分数、嵌套括号 | 切行算法压力最大的一类 |
| **难例** | 30 | `×` 与 `x`、`1`/`l`/`7`、`z`/`2`、上标贴字、分数线过长、涂改重写 | **全在 test 集**，测的是"系统该不该请求人工确认" |
| 自由写 | 50 | 按自己习惯随便写，不照抄 | 最真实，但**没有预设真值**，见 §5 |

划分：95 条 `self_train` / 105 条 `self_test`。

### 页与 split 的实际分布（挑页拍之前必看）

test 不是集中在一个角落，它散在 20 页里：

| 页 | 内容 | train / test |
|---|---|---|
| page_01~12 | 方程、方程组、化简、求导、复合结构 | 每页 8 条 train + 2~3 条 test |
| **page_13~15** | 难例 30 条 | **10 条全是 test** |
| **page_16~20** | 自由写 50 条 | 全是 test，但**真值待补** |

所以"只拍 11 页 test"这个说法不成立。三个选择：

- **最省事：20 页全拍。** 一页 10 行，挑着拍反而要重新对位，容易串行。
- **只拍 test 主力：page_13~15 三页**，拿到 30 条有真值的难例；再补 page_16~20 的自由写（记得补标注）。
- **train 别跳过**：消融实验 A–E 调阈值要用，而且同一批纸顺手就写完了。

## 2. 数据集 B：真正缺的，题型按"错法"分不按"题型"分

`data/work_shotlist.csv` 20 页，**每页一题，照抄 `lines` 列，用 `|` 分隔的行就是一行**。
真值已经标好了（`truth_grade` / `truth_first` / `truth_type` / `baseline`），你不用再做标注。

| 组 | 页 | 要覆盖什么 | 为什么必须有 |
|---|---|---|---|
| 正确过程 | W01~W04 | 基础因式分解、**同题不同解**、提公因式路径、**夹中文叙述行** | 测**冤枉率**。一题多解被判错比不批改更糟；中文叙述行是你独有的结构信息 |
| **伪推导** | **W05~W07** | 过程错、答案对：中间抄错 / 移项写错又改回 / 整行换成另一方程 | **最值钱**。作业帮判"对"，你的系统要判 `fake`。报告里唯一能拉开的差异化证据 |
| 明显错 | W08~W11 | 移项符号错、漏乘漏除、答案代不回、因式分解符号错 | 测首错定位与错因归因 |
| 漏解 | W12~W13 | 只写一个根 / 两边同除 x 丢掉 x=0 | 测 `partial` 与"少了哪个解"是否说得清 |
| 无法判定 | W14~W15 | "这道题我不会" / 应用题叙述 + 式子 | 测诚实降级：`gap`、以及应用题的已知边界 |
| **拍摄退化** | **W16~W18** | 第 3 行涂黑 / 拍糊落阴影 / 写错划掉重写在旁边 | **不是坏数据，是必需品**。用来验证"识别错误不能算学生错"：断言撤回、反例作废、总判定转 `unread` |
| 版式压力 | W19~W20 | 大分式多行过程 / 一页两道题 | W19 测切行；W20 是**已知局限**，不进指标，只记录失败模式 |

### P0 最小集 8 页

`W01, W04, W05, W08, W12, W13, W16, W17`

八页覆盖：正确（含中文）、伪推导、明确错、两种漏解、**两种撤回场景**。
其中 W17 最狠：文字版基线是 `fake`（判"过程不成立"），但那行被拍糊了，
拍照链路**必须**把它撤回成 `unread`。撤回不了就是真缺陷。

#### P0 逐页抄写卡（照这个写，不用另找题目）

**八页的题目和每一行都已经在 `data/work_shotlist.csv` 里**，不存在"去哪找题"这一步：
下面每块就是 `lines` 列按 `|` 拆开的结果。一张 A4 一页，从上往下逐行抄，
第 1 行就是题面（`problem` 列），**不写题号、不写页名**，页名只用在照片文件名上。

⚠️ 两件最容易做错的事：
1. **里面的错是故意的，别下意识改对**（W05 / W08 / W12 / W13 全是设计好的错误过程）。
   真值 `truth_grade` 是按下面这段文本算出来的，抄错一个符号，真值就对不上了。
2. **中文叙述行照抄**，W04 的"两边同乘2得…""所以…"是说明行，不是噪音。

```
W01.jpg   正确过程        真值 pass
  x^2-5x+6=0
  (x-2)(x-3)=0
  x=2 或 x=3

W04.jpg   正确 + 夹中文    真值 pass
  x^2-5x+6=0
  两边同乘2得 2x^2-10x+12=0
  所以 (x-2)(x-3)=0
  x=2 或 x=3

W05.jpg   伪推导           真值 fake（过程错、答案对，最值钱的一页）
  x^2-5x+6=0
  x^2-6=5x
  x^2-5x=6
  x=2 或 x=3

W08.jpg   明显错           真值 wrong（移项符号错）
  2x-6=12
  2x=12-6
  2x=6
  x=3

W12.jpg   漏解             真值 partial（只写一个根，别补 x=3）
  x^2-5x+6=0
  (x-2)(x-3)=0
  x=2

W13.jpg   漏解             真值 partial（两边同除 x 丢掉 x=0）
  x^2=x
  x=1

W16.jpg   拍摄退化         真值 unread（文字版基线 pass）
  x^2-5x+6=0
  (x-2)(x-3)=0
  x=2 或 x=3     ← 写完用黑笔把这一整行涂黑到看不清

W17.jpg   拍摄退化         真值 unread（文字版基线 fake，必须撤回"不成立"）
  x^2-5x+6=0
  x^2-6=5x
  x^2-5x=6       ← 只让这一行拍糊 / 落阴影，其余保持清晰
  x=2 或 x=3
```

W16 / W17 的缺陷**要真的制造出来**，不要修掉、不要重拍一张干净的：
这两页专门验证"识别没读准时不算学生错"，是公开数据集里一张都没有的。
W17 拍照时让阴影只压住第 3 行，或轻微失焦那一行，别整页糊。

### 别拍这些

- **几何题**：`geoagent` 是另一条链路，拍照批改不接它。
- **纯文字应用题**：没有标准解，只能给 `gap` / `unknown`，W15 一页够了。
- **含参分类讨论**：`params.py` 只用于求解，不用于对照学生的分类，拍了也不批。

## 3. 怎么写、怎么拍

A 和 B 的规范**只有一处不同**：A 一页 10 行独立公式，B 一页一题、行数不固定。
其余全部沿用 `docs/采集与切分方案.md` §2。

| 项 | 共同要求 | B 额外要求 |
|---|---|---|
| 纸 | A4 纯白无格 | 同左 |
| 笔 | 黑色签字笔 / 中性笔，别用铅笔 | 同左 |
| 字高 | 7~9 mm，按平时习惯写，**别刻意工整** | 同左 |
| 行距 | 墨迹净空 ≥ 8 mm（唯一硬约束） | 大分式行上下各多留半行 |
| 题号 | **不写**，会被切进单行图 | 不写，**页名就是 id** |
| 第 1 行 | 一条公式 | **写题面**（`problem` 列） |
| 中文 | — | **照抄，别省略**（"两边同乘2得…"）。这是说明行，不是噪音 |
| 姿态 | 手机后置竖直俯拍，纸占画面 70%+，纸四边可见，倾斜 ≤3° | 同左 |
| 光线 | 自然光/柔光，避免单侧强光 | 同左；W16~W18 的缺陷**照做**，不要修掉 |
| 格式 | jpg，不用扫描 App，不裁剪不美颜 | 同左 |

iPhone 先把相机格式改成"兼容性最佳"，否则存的是 HEIC，改后缀没用。
体检脚本会按文件头查这件事。

**B 的关键约束：一页只写一道题。** 切行算法按行带投影切，一页写两题会把两题的行混进同一个过程，
W20 就是专门用来记录这个失败的。题与题之间留空行也没用，别试。

### 命名

```
data/inbox/page_01.jpg  ...  page_20.jpg      # A：对应 data/pages.csv
data/inbox/W01.jpg      ...  W20.jpg          # B：对应 data/work_shotlist.csv
```

两套都放 `data/inbox/`，靠页名区分。A 的页名走 `page_`，B 的走 `W`，不冲突。
注意 `data/inbox/` 在 `.gitignore` 里，照片不会进仓库——这是有意的，别手动改。


**手机整页照会自动走"整页模式"。** `split_page` 短边 ≥ 400 px 时不再用全局 Otsu，
改用局部高通判笔画 + 剔除厚块（桌面/阴影）+ 行带验收（纸边硬边缘、格线、游离孤带）。
实测 P0 八页切行从 1/8 提到 8/8，细节见 `reports/capture_check.md` 与
`tests/test_page_split.py`。M²E 那类 69~309 px 的公式块仍走老路径，历史数字不受影响。

`check_capture.py` 只读不写（除了 `--md` 出的报告），可以反复跑。
`--split` 会实切一遍过程页，把"切出 4 行、期望 5 行"这种错位当场报出来——
这类错误不报，后面所有行会整体错位，而且看起来毫无异常。

## 6. 已经顺手修掉的三件事

体检脚本第一次跑就抓到，不改的话照片拍完也是废的：

1. **train/test 公式泄漏**：`calc_016`（train）和 `hard_027`（test）都是
   `\lim_{x \to 0} \frac{\sin x}{x}`。已把 `hard_027` 换成 `\lim_{n \to \infty} \frac{1}{n}`，
   考察点（lim 下方字挤）不变。技术文档 §5.3 声称"`check_data.py` 已实现检查"，
   但那个脚本从来不存在——检查现在落在 `check_capture.py` 里了。
2. **`workcheck._relate` 崩溃**：`x²+y²=1` 这类多元式子让 `sympy.solve` 返回 `And`，
   `list(And)` 直接抛 TypeError，整页批改崩掉。方程组正是要拍的题型之一。
   已改成解集算不出就跳过（`unknown`），**不顺势判学生错**，并补了回归测试。
3. **W14 字段错位**：`lines` 写成空、`expect_lines` 写成中文，已修。

`eval/work_cases.jsonl` 40 条和 `eval/photo_cases.jsonl` 9 条是构造文本 / 假识别器，

### 7.1 公开数据能替掉一部分，但替不掉 P0 八页

另见 **`docs/公开数据集调研.md`**：已核实 M²E（99,956 个真实试卷多行公式块，
`\n` 自带逐行真值）、HME100K / CROHME、MathWriting、ScratchMath 等六份可获取数据，
以及三份查到但**目前下不到**的（OmniHandwritingOCR / ErrorRadar / EdLight）。
`tools/import_public.py` 负责把它们转成 `labels.csv` / `blocks.jsonl` 形状。
M²E 这条线已经打通到出报告：**`docs/魔搭接入步骤.md`**（注册 → 下载 → 导入 →
`eval/run_line_eval.py` 跑真实版式切行召回率），全程不用等人动笔。
2026-11-11 实测：默认参数 13.4%、train 选参后 test 24.4%——**切行模块对紧凑公式块不适配**，
这个数不能外推到整页作业照，P0 八页反而更必要。

结论：**A 的采集量可以减，B 的「版式压力」组可用 M²E 顶掉一部分**；
但**伪推导**（`W05`）和**拍摄退化**（`W16 W17`）在公开数据里一张都没有，
P0 八页仍必须自己写、自己拍。公开数据只作「外部验证集」单列报数，
不混进 `self_test`，也不能写成"我们采集了 N 条"。

**不要等照片全齐才动手采集**——采集是唯一的串行关键路径，其余都能并行。

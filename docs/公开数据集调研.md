# 公开手写数学数据集调研

版本 v0.1 · 2026-11-10 · 为「手写数据采集清单」做外部数据补位

> 调研方式：搜索引擎 + 数据集卡片 + 官方 API/文件清单 + **实际下载小样验证**。
> 凡是「搜到但没下到」的，本文明确标为不可用，不列进可执行清单。

---

## 0. 先给结论

**公开数据能顶掉数据集 A（单行公式）的量，也能给 B 的「切行」做外部压力测试，但顶不掉 B 的核心——带错因真值的整页解题过程。**

⚠️ 2026-11-11 实测后要改口径：M²E 并未给出一个好看的切行数字，而是**量化暴露了泛化差距**
（默认参数 13.0% / train 调参后 24.0%，均为 test 前 500 块；全量 2000 块 21.9%，
详见 `docs/魔搭接入步骤.md` §7.1 与 `reports/eval_lines.md`）。
它的价值是「发现切行模块对紧凑公式块不适配」，不是「证明切行很准」；报告里别把它当成功证据。

原因很具体：`mathagent/workcheck.py` 吃的是**一行一条的文本过程**，判定要「相邻两式能不能互推」。一份数据要能进主指标，必须同时满足三条：

1. 真实手写的**整页 / 多行**图像；
2. **逐行 LaTeX 转写**（不是整块一个字符串、更不是只有最终答案）；
3. 标了**结论 / 首错行 / 错因**（`truth_grade` / `truth_first` / `truth_type`）。

查下来：单行公式集有 ①②没③；真实学生草稿集有①③但**没有②**；最接近的 ErrorRadar、OmniHandwritingOCR 目前**下不到**。所以 `data/work_shotlist.csv` 的 P0 八页仍然要自己写、自己拍——尤其**伪推导**和**拍摄退化**两组，公开数据里一张都没有。

能省的是量：A 的 200 条不必全拍，B 的「版式压力」组可以用 M²E 替掉一部分。

**另一个必须说的口径问题**：这些数据集几乎全是 `CC BY-NC*`（非商业）+ 署名，有的还带 SA（相同方式共享）。课程项目/学术用途没问题，但报告里要单列一节「外部验证集与许可」，**不能写成「我们采集了 N 条」**，也不能把公开数据混进 `self_test` 去报自采指标。分开报反而是加分项：外部效度。

### 逐条说明与缺口

**① M²E —— 对本项最值钱的一份。** 文件清单已通过魔搭 API 核实：`images.zip` 543,249,796 B（LFS）、`train.jsonl` 13.3 MB、`val.jsonl` / `test.jsonl` 各 1.67 MB、`M2E.json`、`README.md`。标注样例：

```
{"name": "1.jpg", "tex": "9 . 9 \\times 3 . 8 + 9 9 \\times 6 . 2 \\n = 9 . 9 \\times \\left( 3 . 8 + 6 . 2 \\right) \\n = 9 . 9 \\times 1 0 \\n = 9 9"}
```

`\n` 直接给出逐行真值，可以拿去压 `mathagent/lines.py` 的切行算法：拿整块图切行，把切出的行数与 `n_lines` 比，就是**真实版式下的切行召回率**。
实测（test 全量 2000 块）：默认参数 13.0%、train 选参后 24.0%（均为前 500 块）／
21.9% [20.0, 23.8]（全量）。主要失效是行粘连欠切——2000 块里有 606 块真值 ≥3 行却被
并成一行，根因是单条高带时 `split_tall` 拿自己的高度当参照、永远不触发再切。
因为 M²E 是 70~300 px 紧凑小图，而 `split_page` 的参数来自整页作业照。
**两种分布不同，不能拿这个数说拍照批改不准，也不能拿它当切行准确的证据。**

三个坑：它是**公式块不是学生解题过程**，没有对错/错因；含 `\t` 竖式对齐列（我们的行模型不认）；数字被拆成空格（`"1 5 . 4"`），去空格是有损启发式，所以导入时**永远保留 `tex_raw`**。

**② HME100K —— 领域最贴合 A。** 中文 K12 手写公式，比 MathWriting 的 Wikipedia 高等数学公式贴近你的题型得多。但授权最乱：官方 `ai.100tal.com/dataset` 页面可访问（本机探测 200），老仓库写的是要发邮件到 `HME100K@hotmail.com` 申请；Kaggle 镜像 `prajwalchy/hme100k-dataset` 744 MB **自报 MIT**（这是上传者填的，不等于原始授权）；HF 镜像 `SoyVitou/Latex-Math-HME100K` 99,109 行 / 2.29 GB；MaRDI 收录的 figshare 打包版 DOI `10.6084/m9.figshare.30341779.v1` 标 **CC BY 4.0**（连同 CROHME 一起）。**建议优先 figshare 版**，并在报告注明「第三方镜像，仅用于学术评测」。

**④ MathWriting —— 已端到端实测。** 下载 1,620,634 B 摘录包，解出 `train/valid/test/symbols/synthetic` 各 100 条 InkML；`tools/import_public.py` 渲染出 24 张 PNG，写进 `labels.csv`。**但 `--check-parse` 显示只有 9/24 条真值能被本项目 CAS 解析**——因为标签是 `\vartheta=-\frac{log\frac{...}}{...}` 这类 Wikipedia 公式，不是初中方程。结论：**只能做识别鲁棒性测试，不能当求解/批改评测集**。想测求解链路，用 HME100K/CROHME 或自己拍的 A。

**⑤ ScratchMath —— 错因体系可借鉴，图也能用。** 7 类错因：计算错误 / 题目理解错误 / 知识点错误 / 答题技巧错误 / **手写誊抄错误** / 逻辑推理错误 / 注意力与细节错误。注意它是**按「认知错因」分类**，和本项目的**按「动作错因」分类**（移项变号 / 漏乘漏除 / 漏解 / 增根）不是一套东西，别硬映射。最大价值是真实草稿图：抽几十张人工标「哪行看不清」，就能验证 `_apply_uncertainty` 在**真实涂改**上是否真的撤回了断言——这不需要逐行 LaTeX 真值。缺口很明确：**没有逐行 LaTeX**，且以小学应用题为主，`grade()` 直接喂不进去。

**⑥ CASIA-HWDB —— 补中文叙述行。** 你的过程页里有「两边同乘2得」「由①得」，这类中文行现在 `route.py` 当 prose 处理。HWDB2.x 的 52,230 个文本行能测切行对中文行的表现。纯中文、无公式混排，只能做单侧压力测试。

## 3. 拿到之后怎么用（建议的最小动作）

| 顺序 | 动作 | 产出 | 顶掉什么 |
|---|---|---|---|
| 1 | MathWriting 1.5 MB 摘录 + 导入 | 24~300 张渲染图 + `labels.csv` | 冒烟验证识别链路（**已完成**） |
| 2 | 注册魔搭 → 下 M²E → 导 500~2000 块 | `blocks.jsonl` / `lines.csv` + `reports/eval_lines.md` | **切行的外部压力测试**（实测暴露小图泛化差距），替掉 B 的版式压力组；逐步命令见 **`docs/魔搭接入步骤.md`** |
| 3 | 下 ScratchMath 两个 parquet → 抽 50 张 | 真实涂改/草稿图 | 定性验证「不确定性传播」在真实手写上撤得对不对 |
| 4 | figshare 版 HME100K + CROHME → 抽 200 张 | 单行小图 + 真值 | 补 A 的一部分，出 ExpRate / CER 外部对照 |
| 5 | 自采 **只保留 B 的 P0 八页** | `W01 W04 W05 W08 W12 W13 W16 W17` | **伪推导 + 拍摄退化**——公开数据一张都没有，必拍 |

第 2 步是当前性价比最高的一步：不用等人动笔，就能给「拍照批改」补上真实试卷版式的数字。下载 / 验收 / 导入 / 评测的完整命令见 **`docs/魔搭接入步骤.md`**，评测入口 `eval/run_line_eval.py` 已就绪（默认参数 baseline → train 调参 → test 报数，脚本强制 train/test 分离）。第 5 步仍是**唯一串行关键路径**，别等公开数据齐了再动笔。

口径上：公开数据单独成节叫「外部验证集」，指标与 `self_test` 分表；技术文档 §6 的 8 个指标是给自采数据定义的，换数据集要重新说明指标含义（例如 CROHME 惯用 CER，本项目用 ExpRate / 语义等价率）。

## 5. 导入脚本

`tools/import_public.py` 纯离线、不联网、不改原始包，输出统一到 `data/public/<dataset>/`（已加进 `.gitignore`：体积大且多为非商业许可，不入库）。每个输出目录带 `SOURCE.json` 记录出处与许可。

```bash
# 先看下载到的东西对不对，不写文件
F:/PyCharm/python.exe tools/import_public.py probe mathwriting --src D:/dl/mw-excerpt.tgz
F:/PyCharm/python.exe tools/import_public.py probe m2e --src D:/dl/M2E

# MathWriting / CROHME：InkML → PNG + 与 data/labels.csv 同形状的 labels.csv
F:/PyCharm/python.exe tools/import_public.py mathwriting --src D:/dl/mw-excerpt.tgz --limit 100 --check-parse
F:/PyCharm/python.exe tools/import_public.py mathwriting --src D:/dl/crohme --label-field truth --limit 200

# M²E：多行 tex → blocks.jsonl（保留 tex_raw）+ lines.csv（逐行）
F:/PyCharm/python.exe tools/import_public.py m2e --src D:/dl/M2E --limit 2000 --despace

# ScratchMath：parquet → 图片 + metadata.jsonl（需 pyarrow）
F:/PyCharm/python.exe -m pip install pyarrow
F:/PyCharm/python.exe tools/import_public.py scratchmath --src D:/dl/ScratchMath
```

设计要点：

- **M²E 的去空格是可选的、有损的**，`blocks.jsonl` 永远留 `tex_raw`；`has_align` 标出含 `\t` 的竖式块，用之前先滤掉。
- **MathWriting 的 `--check-parse`** 会统计真值能不能被 `mathagent.latex.parse` 解析，直接告诉你这批数据能不能进求解类指标（实测 9/24）。
- `--label-field` 兼容 CROHME 的 `truth`（并剥掉外层 `$...$`）。
- 输出 `labels.csv` 的 `split` 映射：`train → self_train`，`valid/test → self_test`，`type` 带 `公开-` 前缀，**不会和自采数据混淆**。

离线回归测试：`tests/test_import_public.py` 5 项，用构造的 InkML 与 M²E 卡片样例，不联网、不依赖 pyarrow。

**M²E 专用两段（2026-11-10 补齐）**：

- `tools/fetch_m2e.py`：封装官方 `modelscope` CLI 的分步下载（默认 dry-run 只打印命令），
  下完自动验收文件清单、jsonl 可解析性、**Git LFS 指针检测**，并把 zip 内图片按 basename 摊平、
  核对与标注 `name` 的对齐率。token 只从环境变量读，不打印、不落盘。
- `eval/run_line_eval.py`：把 `blocks.jsonl` 喂给 `mathagent/lines.split_page`，
  用标注 `n_lines` 当真值，报行数完全一致率（bootstrap 95% CI）、MAE、bias、过切/欠切、按行数分层。
  **参数只准在 `train` 上调，指标只准在 `val/test` 上报**，脚本层面禁止在 test 上边调边报；
  报告自带口径警告（只比行数不比框位置、CC BY-NC 4.0、外部验证集不得混入 `self_test`）。
  输出 `reports/eval_lines.md` / `.json`，`--debug N` 导出画框图。
- 离线护栏 `tests/test_m2e_pipeline.py` 9 项：假 zip/LFS 指针、图片名对齐、指标计数、
  真实 `split_page` 接口连通、调参纪律、smoke 报告不覆盖正式报告。

逐步操作见 **`docs/魔搭接入步骤.md`**。

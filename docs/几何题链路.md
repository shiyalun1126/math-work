# 几何题链路：题干 + 图形

> 目标：一页照片上有中文题干、也有图形，系统能读懂结构、把理解结果画给你看、再给答案。
> 定位不是"替你做出来"，而是"读错了你能一眼看出来"。

## 一、为什么不复用公式链路

公式题的中间态是**一串符号**（LaTeX），几何题的中间态是**一张关系网**。

硬塞进 LaTeX 的后果实测过：让模型"把图里的数学式子转写为 LaTeX"，它会把整段中文题干连同题号一起塞进去：

```
1. 如图，在\triangle ABC中，\angle C=90^{\circ}，AC=6，BC=8，D是AB的中点，求CD的长。
```

这段字符串拿给符号解析器必然失败。失败得很安全（不会给错答案），但什么也没解决——用户看到的是一句「等号数量异常：2 个」，只会以为系统坏了。

所以几何链路是独立的 `geoagent/` 包，和 `mathagent/` 不共用中间表示。

### 入口判断（`mathagent/route.py`）

两个页签并排摆着，投错是常事。既然识别已经把整页文字读出来了，就不该让用户自己发现走错了门：

| 判据 | 结论 |
|---|---|
| 成句中文（≥ 6 个汉字）且几何特征词打分 ≥ 3 | 几何题 → 就地转 `geoagent` 跑，重绘图直接画在公式页签下面 |
| 成句中文但不像几何题 | 文字题（应用题）→ 说明「公式链路读不懂叙述」 |
| 否则 | 当算式走原链路 |

**必须是成句中文**这条硬要求是为了不误伤：`\angle A + \angle B = 180^\circ` 是个正儿八经的算式，不能因为出现 ∠ 就判成几何题。算子里顶多出现 `\text{cm}`、`\text{度}` 这种单位，凑不到 6 个汉字。

还有一处容易漏：整页题在投票阶段常被全判「无法解析」，`chosen` 是空串。只盯着 `chosen` 判断入口，永远发现不了投错门——要拿**所有候选里最长的那条**兜底。

## 二、四步链路

```
照片
 ├─ 1. 读图      两路 VLM 各自输出结构化 JSON（点、线段、圆、标记、位置）
 ├─ 2. 补全      题干整句声明编译成约束（正方形/平行/等长）、交点与「点在线上」
 ├─ 3. 交叉校验  题干文字 ↔ 图上标记 ↔ 两路结果
 ├─ 4. 求解      条件翻译成坐标约束，数值解出图形；证明题则验证结论
 └─ 5. 重绘      按结构重画一张图，和原图并排给你看
```

第 2 步是后补的，但位置很关键：必须先于校验。校验拿到的如果是「只有四角直角的矩形」，它会如实说「结构自洽」——因为确实没矛盾，只是少读了三条边等。

### 读图（`read.py`）

提示词要 JSON，不要 LaTeX。规则里写死的几条：

- `points` 只写单个大写字母
- `marks.type` 只能是 `right_angle` / `equal_length` / `parallel` / `midpoint`
- **看不清就填 `null` 或 `[]`，不要猜**
- `problem_text` 一字不漏照抄，**「……与……交于 P」「求证：……」这类句子最容易漏**
- 点是交点时，写成「F 在 AE 上，也在 CD 上」——**不要**写「F 是 AC 与 DE 的交点」，字母实测会错两个

模型的输出质量问题（截断、代码块包裹、`<think>` 段、中文标点）在 `parse_json` 里统一收拾，截断的 JSON 会从后往前退、逐次补括号救回来。

**智谱全系 `max_tokens` 硬上限 1024**，写 1200 直接报 400。按通道给不同值，撞上了自动退到 1024。

**小图必须放大**。手机截图里裁出来的题图常常只有 300px 宽，中文小字在 640 下糊成一团，模型会把整句条件吞掉——同一张图放大到 1100 后 `problem_text` 才完整、`goal` 才从「题干未写完」变成 `CE=CF`。几何链路用 `min_side=1100`，公式链路仍是 640。

### 交叉校验（`crosscheck.py`）

这是几何题比公式题更有胜算的地方：**同一件事往往说两遍**。题干写「∠C = 90°」，图上还画个直角小方块；题干写「D 是 AB 中点」，图上还画等长标记。

四条比对：

| 级别 | 含义 | 例子 |
|---|---|---|
| 一致 | 文字与图形互相印证 | 题干 ∠C=90°，图上 C 处有直角标记 |
| 补充 | 只有图上才有 | 题干只说"切线"，图上标了直角（半径 ⊥ 切线） |
| 存疑 | 该有的没找到 | 题干称中点，图上没找到等长标记 |
| 冲突 | 两处说法互斥 | 题干说 ∠C=90°，图上直角标在 A |

**判定刻意保守**：宁可报"存疑"也不轻易报"冲突"。误报冲突会让人不再相信提示，那这套机制就白做了。

跨通道比对时，"一路有、另一路没有"只记为补充/存疑，不当冲突——漏读远多于错读，把漏读当冲突会天天误报。真正危险的只有"同一处给出互斥说法"。

### 求解（`solve.py`）

坐标法而不是定理搜索：定理搜索要建题库和推理规则，规模无上限；坐标法只要能把条件写成等式，绝大多数初中题都能算，而且算完能代回检验。

支持的条件：

- 定长 `AC = 6`
- 直角（图上标记 + 题干 ∠=90°）
- 中点 `D 是 AB 的中点`
- 等长 `|AB| = |AC|`
- 平行
- 垂直 `AB ⊥ CD`
- 共线（`交 AB 的延长线于 P`、`AB 是直径`、`AE 与 CD 相交于 F`）
- 点在线上 `F 在 AE 上`，并要求 F 落在两端**之间**（不是延长线上）
- 特殊图形整句声明：`四边形 ABCD 为正方形` / 矩形 / 菱形 / 平行四边形 / 正三角形
- 点在圆上
- 角度 `∠A = 25°`
- 方向约束（`P 在 B 外侧`）

前九条里有一半不在图上画任何符号，只能从题面读——这部分由 `relations.py` 统一编译：它把「一句中文」翻成「若干条等式」，并把补了什么写进求解步骤，用户核对时能看到出处。

用 Levenberg–Marquardt 阻尼最小二乘解，残差要小于 `1e-4` 才算解出来。

### 重绘（`render.py`）

画图有三档坐标可用，按「像不像用户手里那张图」来选，不按「准不准」：

| 依据 | 何时用 | 说什么 |
|---|---|---|
| 解出的**真实坐标** | 图形被条件唯一确定 | 「按解出的真实坐标重绘，几何关系是准的」 |
| 读到的**各点位置**（`pos`） | 条件不足、或有自由度 | 「按读到的各点位置重绘，形状比例不作数」 |
| 环形示意 | 连位置都没读到 | 「只看点线关系」 |

第二档是本轮补的。以前只有「解出坐标」和「环形布局」两条路，而坐标为空的判据是"目标算出来了没有"——于是条件不足的题一张图都画不出来，8 个点被摆到圆周上，A 在正上方、D 跑到底下、E 跑到左边。用户看一眼就说「重绘也太偏离题了吧」。

其实图上点线是读对的，只是答案定不下来，这是两件事。现在坐标只要残差合格就存下来，重绘不再跟着答案走。

这一步是最容易被接受的校验手段：公式认错了要自己对照字符串，图形认错了看一眼重绘图就知道少没少线。

但"画对了结构"和"画得让人看得懂"是两件事。第一版只做到了前者，结果 g2 的重绘图被一眼判为"错"——五件事没做：

| 问题 | 表现 | 修法 |
|---|---|---|
| **镜像** | A 跑到右边、P 跑到左边，和原图左右颠倒 | 读图时多要一个 `pos` 字段（各点 0–100 的近似位置），先拿它当求解初值，解完再用 Kabsch 做一次纯旋转对齐 |
| **错标直角** | 直角方框画在两条弦之间，原图明明画在半径与切线之间 | `repair_marks()`：题干说了切线时，切点处的直角强制归到「半径 ⊥ 切线」上，并说明改了什么 |
| **点悬空** | P 只有一条切线连着，和 B 断成两截 | `_extra_links()`：按共线关系把相邻两点补连起来 |
| **目标不明** | 图上完全看不出在算哪个角/哪条边 | 目标量标红：角度画弧并写度数，长度加粗并写数值，文字带描边免得被线条压住 |
| **标签压线** | 证明题的「求证 CE = CF」被 CF 那条竖线穿过去 | `_free_spot()`：在图的上下左右几个候选位里，挑离所有线段最远的那个 |

最后两条最要紧。用户看的是图，不是求解步骤里那行 `∠P = 40°`；图上没标出来，就等于没说清在算什么——哪怕数字本身是对的。

### 解题过程（`reason.py`）

`sol.steps` 本来是写给开发者的日志（「读入 6 个点」「残差 2e-14」）。第一版直接拿它当解题过程，用户回了一句：**「让你给解题过程，不是把题干条件再罗列一遍」**。

第二版换成坐标法，跑出来是这样：

```
一、建系  以 A 为原点、AB 为 x 轴，设 AB = 1
二、坐标  A(0,0) B(1,0) C(1,1) D(0,1) E(0.366, 1.366) F(0.268, 1)
三、核对  表格：题干每条条件 → 代回坐标后的实测值
四、目标  CE = √[(1−0.366)²+(1−1.366)²] = 0.732；CF 同样
```

用户又指出两处：**「你不知道他们都是多长，这都是你假设的」「你又怎么假设出来 E、F 的坐标」**，还有最要紧的第三句：**「几何题尽量还是用几何思维，谁平行，哪个角相等，用推理的形式」**。

三条都成立。题目没给长度时 `设 AB = 1` 是凭空塞进去的；E、F 的坐标更是黑箱，学生看不到它们怎么来的。

所以另起一层 `reason.py`：**前向链推理**。事实库 + 规则库，从条件和图形结构出发，一步步套定理。同一道题现在长这样：

```
3. ∵ AC ∥ DE，CD 是截线
   ∴ ∠ACD = ∠CDE（两直线平行，内错角相等）

4. ∵ AD = CD（△ACD 是等腰三角形）；顶角 ∠ADC = 90°
   ∴ ∠ACD = 45°（等腰三角形两底角相等，三角形内角和 180°）

5. ∵ ∠ACD = ∠CDE；∠ACD = 45°
   ∴ ∠CDE = 45°（等量代换）
   …
20. ∵ ∠CEF = ∠CFE
   ∴ CE = CF（等角对等边）
```

（`AC ∥ DE` 按题面写的 `DE∥AC` 呈现，这里为排版统一。）

#### 引擎怎么组织

| 部件 | 内容 |
|---|---|
| **事实** | `eqseg`（等长）、`eqang`（等角）、`angval`（度数）、`right`、`para`、`mid`、`coll`、`len`、`cong`（全等）、`sim`（相似）；圆的 `center`、`on_circ`（点在圆上）、`diam`（直径）、`tang`（切线）。每条带「依据」和「依赖」 |
| **规则** | 内错角、**同位角**、三角形内角和、角的分割、等量代换、**中点分段**、**全等判定（SSS/SAS/ASA/AAS/HL）与性质**、**相似判定（AA/SAS/SSS）与性质**、等边对等角／等角对等边、等腰顶角底角、同射线角相等、勾股、斜边中线、**圆（圆周角、圆心角、内接四边形、弦切角、切线长、垂径定理）**、正弦定理、平角 |
| **验算** | 每条规则给出的结论，都在解出的图形上量一遍，对不上就整条丢弃 |
| **输出** | 从目标回溯依赖做拓扑排序，只渲染这条链用到的事实 |

**验算是这套东西的底线**。规则触发靠结构（共线、连线、平行），结论落地前必须过数值检查——推理链漂亮但错一步，过不了这关。所以它不会「编」出一条自洽但错误的证明。

#### 全等 / 相似：判定和性质要分开写

判完全等本身不是目的，取用对应边、对应角才是。所以 `cong` 是两类规则：

```
∵ AB = BC；BE = CF；∠ABE = ∠BCF
∴ △ABE ≌ △BCF（边角边 SAS）

∵ △ABE ≌ △BCF
∴ AE = BF（全等三角形的对应边相等）
```

判定要看六种顶点对应（两个三角形名只给了两个字母集合，谁跟谁对应得靠条件定），所以每个三角形对穷举 6 种对应，哪种凑得齐条件就用哪种。凑的时候有三条硬规矩：

| 规矩 | 为什么 |
|---|---|
| **公共边可以算条件，但不能只靠它** | △ABD 与 △ACD 共用 AD，SSS 离了这条就证不出来（三线合一全靠它）；可若允许「AB = AB」随便凑，SSS 一条真条件都不用就能"证"出全等。所以规则是：公共边计入，但至少要有两条真条件 |
| **对应关系要认三个字母的顺序** | 「△ADE ∽ △ABC」和「△AED ∽ △ABC」是两个不同的断言。存事实时只在「整体轮换 + 整体翻转 + 两三角形对调」下归一，绝不把字母简单排序 |
| **写出来的顺序按题目的来** | 引擎内部用规范写法去重，但结论那行照抄题目（问 △ADE ∽ △ABC 就写这个顺序），学生对着题看不会以为答错了 |

相似多一道坎：`sim` 要带相似比，而且这个比只能由**已知长度**算，不能拿量出来的坐标倒推——否则又回到"坐标法假装成推理"。比例未知时 `k = None`，此时只推对应角相等，不推长度。有了 k 就能落地：

```
∵ △ABC ∽ △ADE，相似比 0.5
∴ BC = 6（相似三角形对应边成比例）
```

#### 同位角：相似唯一的入口

`DE∥BC` 截出 △ADE 时，∠ADE 与 ∠ABC 在截线 AB 的**同一侧**——那是同位角，不是内错角。早期只写了内错角，于是「平行 → 两角相等 → AA」这条路根本起不了步，AA 判定等于没有入口。补的时候有个坑：谁当 L1、谁当 L2 决定「截线上哪个点在 X 外侧」，两个方向都得走一遍，否则 ∠AED 与 ∠ACB 那一对就漏了。

#### 辅助线：八种造法，全都验得了

推不动时的第一反应不该是认输——几何题卡住十有八九是少了一条线。做法是把候选辅助线挨个接上**重推一遍**，哪条能走通就报哪条。

关键在于「验算得了」。连线型的辅助线只是往图上加边，端点都在图上；其余七种要造新点，可这些新点的位置是**由作图本身算出来的**——垂足就是投影、中点就是平均、交点就是两直线求交、旋转就是绕点转、翻折就是投影再取对称。既然算得出坐标，它就和图上读到的点一样能参与验算，也就敢写进答案里。

| 造法 | 怎么来 | 造出来的条件 |
|---|---|---|
| **连接** | 两点都在图上、又没连线 | 新边，凑三角形 |
| **作垂线** | 过一点向一条边作垂线 | 垂足 + 直角（`作图（作垂线）`） |
| **取中点** | 三角形一条边的中点，连成中线 | 中点 + 两条等长 |
| **延长** | 一条线延长出去，与另一条线相交 | 交点 + 共线、在线段上 |
| **作平行线** | 过一点作某条边的平行线，交另一条边于新点 | 平行（→ 同位角、内错角 → AA 相似） |
| **作角平分线** | 从顶点引平分线，交对边于新点 | 一对相等的角 |
| **旋转** | 把一个三角形绕它的一个顶点转 60°/90° | 一对全等三角形 + 旋转角 |
| **翻折** | 一点关于一条直线对称过去 | 折痕垂直平分对应点的连线 |

三种变换型辅助线的阈值：

- 平行线的交点必须真落在目标边上（参数 `s ∈ (0.08, 0.92)`），否则那条「平行线」只是擦过去，不产生任何三角形
- 角平分线的交点必须在射线上（`t > 0`），反向延长出去的不是角平分线
- 旋转如果转过去的点正好落在图上已有的点（正三角形绕顶点转 60°，第三个顶点就是现成的），就直接用那个点，不另起名字
- 翻折的折痕够不着（垂足参数 `t ∉ (-0.3, 1.3)`）就不试

| 规矩 | 为什么 |
|---|---|
| 共线的两点不连 | 连上去不产生新三角形，白跑一趟 |
| 垂足落在端点附近（`t < 0.12` 或 `> 0.88`）就不作 | 那条「高」本来就画在图上了 |
| 垂足、中点、交点已经和某个已知点重合就不造 | 造出来只是给同一个点换个名字 |
| 延长只走到 2.5 倍边长以内 | 再远就不是这道题要的那条线了 |
| 先连线，再作高、取中点，再平行、角平分，最后才是延长与变换 | 越往后越不确定，按把握排序 |
| **作图给出的关系也要先验算** | 公式里写错一个符号，得到的等长、平行全是假的，而且它们会被当成出发条件，让整条链看起来天衣无缝。所以 `_fact_holds()` 把每条作图关系先在解出的图形上量一遍，对不上就整条丢弃 |
| 报出来要明说是辅助线 | `> **辅助线**：过 C 作 H ⊥ AB 于 H。` 旋转、翻折写 `辅助变换`——图上没有的东西得让学生知道是自己该添的 |

代价是每条候选都要跑一遍完整推理（实测 0.02–0.07s/次，候选 11–19 条），所以候选只挑与结论有关的点，且各类都有上限。

旋转这条能走通多远，看一道经典题（正三角形内一点 P，PA=3、PB=4、PC=5，求 ∠APB）：

```
> 辅助变换：把 △BPA 绕 B 旋转 60° 得 △BKC。

1. ∵ 把 △BPA 绕 B 旋转 60° 得 △BKC      ∴ △ABP ≌ △CBK（旋转保距）
2. ∵ △ABP ≌ △CBK                        ∴ ∠BKC = ∠APB（全等三角形的对应角相等）
3. ∵ 旋转 60°                            ∴ ∠KBP = 60°
4. ∵ BK = BP，顶角 ∠KBP = 60°            ∴ ∠BKP = 60°（等腰三角形两底角相等）
5. ∵ CK = 3，KP = 4，CP = 5，3²+4²=5²     ∴ ∠CKP = 90°（勾股定理的逆定理）
6. ∵ ∠BKP = 60°，∠CKP = 90°              ∴ ∠BKC = 150°（角的和）
7. ∵ ∠BKC = ∠APB，∠BKC = 150°            ∴ ∠APB = 150°（等量代换）
```

第 5 步的「勾股定理的逆定理」是这一轮补的：没有它，3、4、5 三条边长算得再准，也走不到「所以是直角三角形」。


#### 圆：五条角度定理 + 两条长度定理 + 三条圆幂定理

圆是唯一一类「条件全藏在一句话里」的图形——「点 C 在圆上」「AB 是直径」「PC 是切线」，图上往往什么都不标。所以先把这些整理成事实：`center`、`on_circ`、`diam`、`tang`，另外**同圆半径相等**直接落成 `eqseg`（等腰三角形 OBC 全靠它）。

| 定理 | 产出 |
|---|---|
| 直径所对的圆周角是直角 | `right`（再展开成 90°） |
| 同弧所对的圆周角相等 | `eqang` |
| 圆内接四边形的对角互补 | `angsum 180°` |
| 同弧所对的圆心角是圆周角的两倍 | `angval` |
| 弦切角等于它所夹的弧对的圆周角 | `eqang` |
| 过圆外一点引两条切线，切线长相等 | `eqseg` |
| 垂径定理（直径垂直于弦，平分弦） | `mid` → `eqseg` |
| **相交弦定理**（点在圆内，PA·PB = PC·PD） | `prod` |
| **割线定理**（点在圆外，PA·PB = PC·PD） | `prod` |
| **切割线定理**（PT² = PA·PB） | `prod` |

圆幂这三条产出的是**乘积关系**，原来的事实库里只有「谁等于谁」，装不下。所以新增了 `prod` 这种事实：`((PA,PB),(PC,PD))` 表示两段的积相等；再配一条 `_r_prod_solve`：四段知道三段，第四段就出来。切线那条要小心——等式左边是 `PT·PT`，未知量出现两次，得**开方**而不是除法，写成一次方程一定算错。

```
1. ∵ AB、CD 是过点 P 的两条弦         ∴ AP·BP = CP·DP（相交弦定理）
2. ∵ AP·BP = CP·DP；AP=2；BP=6；CP=3   ∴ DP = 4
```

两条地方必须小心：


- **「同弧」和「同侧」得自己判**。题面不会写「C、D 在弦 AB 同侧」，只能按解出来的位置算叉积。判错了结论就过不了数值验算，整条丢弃——不会留下一条漂亮的假证明。
- **圆心角只能取画出来的那个**（恒 ≤ 180°）。题目若问优弧上的圆心角，真实值是 360° 减出来的，硬写 `∠AOB = 250°` 学生会以为图画错了，所以这种情形直接跳过。

g2（直径 + 切线 + ∠A = 25°）以前退回坐标法，现在是六步纯几何：

```
1. ∵ AB 是直径，C 在圆上  ∴ ∠ACB = 90°（直径所对的圆周角是直角）
2. ∵ ∠BAC = 25°，∠ACB = 90°  ∴ ∠ABC = 65°（三角形内角和）
3. ∵ ∠ABC = 65°  ∴ ∠CBP = 115°（平角）
4. ∵ CP 是切线，CB 是过切点的弦  ∴ ∠BAC = ∠BCP（弦切角）
5. ∵ ∠BAC = ∠BCP = 25°  ∴ ∠BCP = 25°
6. ∵ ∠CBP = 115°，∠BCP = 25°  ∴ ∠BPC = 40°（三角形内角和）
```

第 3 步的「平角」原来永远走不出来：`_r_straight` 写的判据是 `v in (x, a, b): continue`，把唯一正确的情形（顶点就是中间那个点）也挡掉了——拿端点当顶点，两条射线同向，两个角相等而不是互补。

#### 直径不能猜

以前 `collinear_groups` 里有一句「圆心 + `through[0]` + `through[1]` 三点共线」，等于默认前两个圆周点就是一条直径。撞上「A、B、C 在圆上」这种最普通的条件，它就给出「A、O、B 共线」，图形立刻自相矛盾，残差 0.5 却看不出哪条错了。现在改成真去量：图上三点大体共线（叉积 < 8%）、且 O 落在两点之间，或者题干明说「AB 是 ⊙O 的直径」。

#### 长度一律符号化

题目没给数值时，把第一条边定为 `a`，坐标按它归一化，于是所有长度都长成 `a`、`√2a`、`a/2`，输出开头写明「题目没有给出具体长度，下面的长度都用 a 表示（a = AB；结论与 a 取多大无关）」。这样既没有凭空数字，也不用假装知道边长。

#### 坐标法退为兜底

推理推不出来（缺规则，或图形结构不够）时仍走坐标法，`explain.write(p, sol, force_coords=True)` 可以强制指定。g2（圆 + 切线）原来是典型例子，现在走推理了；剩下走兜底的主要是缺规则的特殊图形。

#### 三个实现上的坑

| 坑 | 表现 |
|---|---|
| **`_ang(顶点, 点, 点)` 参数顺序** | 我在这上面错了七处，症状是「∠ACD 被当成 ∠CAD」，整条链全歪。角度一错，验算能挡住结论，但挡不住中间步骤 |
| **同一个坑还藏在「从名字拆顶点」里** | `_ang(arms[0], name, arms[1])` 把顶点写成了 `arms[0]`：「∠A = 25°」被记成 ∠ABC，「求 ∠P」变成求 ∠PCB。补圆的时候又踩了一次——凡是「由名字反推顶点」的地方，顶点都必须是名字本身 |
| **`kb.val("angval", 角)` 查不到** | 事实存的是 `(角, 度数)`，拿角名当整个参数查永远是 None。得单独写个 `angval()` |
| **共线的两点也是三角形的边** | F 在 AE 上时，图上只有 AE 一条线，但 EF 是 △CEF 的边。不认这一点，最后一步「CE=CF」就凑不出三角形 |

#### 局限

- 规则是手工列的，覆盖初中常见定理：平行（内错角、同位角）、等腰、内角和、勾股（正反两用）、斜边中线、全等判定 SSS/SAS/ASA/AAS/HL、相似判定 AA/SAS/SSS，圆这一路有圆周角、圆心角、内接四边形、弦切角、切线长、垂径定理、直径圆周角、相交弦、割线、切割线。**没有**：四点共圆的判定、托勒密定理、切割线定理的逆定理。
- 辅助线支持八种：连接、作垂线、取中点、延长、作平行线、作角平分线、旋转、翻折，全都靠「造出来的点坐标算得出」这一点保证可验算。**没有**：需要连作两步的构造（先作垂线再取中点之类）、绕非顶点旋转的复杂变换、位似。
- 这一步用了正弦定理（高中内容），输出末尾会注明「按初中要求可作垂线用直角三角形求解」。
- 推不出来就走坐标法，不会硬凑。

## 三、七个必须踩过的坑

### 1. 文字必须能补图形结构

模型经常只把画出来的两点放进 `circles[].through`，漏掉"点 C 在圆上"这种纯文字条件。漏掉的后果很具体：C 就成了一条射线上的自由点，答案直接变成不唯一。

同理，"PC 是切线"在图上未必有直角标记（模型可能把直角标成了 ∠ACB，那是直径所对的圆周角，虽然也对，但不是切线条件）。切线必须垂直半径，这条只能从文字补。

`enrich_from_text()` 负责这件事，补了什么会明写在求解步骤里。

**注意顺序**：必须先 `enrich_from_text` 再 `repair_marks`。补齐前 C 还不在圆周点集合里，`tangent_pairs()` 找不到切点，标记就更正不了——第一版顺序写反，改了没反应。

### 2. 数值解会退化

不加约束，优化器会发现"把所有点缩到原点"最省事：叉积全为 0、到圆心距离全相等、角度在零向量上按 1.0 兜底，于是所有残差一起归零，解出一个看着成立的空壳。g2 实测就得到过 A=B=C 全重合的假解。

`build_constraints` 末尾给每一对点加了最小距离惩罚（`0.08 × scale`），测试里有一条专门守这个。

但只加距离惩罚不够：纯角度题（g2 只有 ∠A=25° 和一堆垂直/切线关系）没有任何尺寸约束，整个图形可以自由缩放，优化器会把它压到惩罚线附近，残差卡在 1e-3 下不去，8 个起点里只有 1 个能收敛。现在改成**钉住一条边的长度**做定标——图形整体缩放不影响任何角度，答案不变，但病态消失了（收敛率 6/8）。配合 LM 阻尼，g1/g3/g4 都是 8/8。

### 3. 目标只能从「求……」里找

一开始把整段题干拿来搜 `∠([A-Z])`，结果题干里的已知条件 `∠C = 90°` 被当成"求 ∠C"，算出来一个 53.13° 的假答案。

现在只从 `goal` 字段（或题干里最后一个"求"之后）解析目标。

### 4. 朝向不能听天由命

求解时为消掉雅可比的零空间，会强制把 0 号点放在原点、1 号点压到 x 轴上——这一步顺手把整个图形转向了"AB 水平"。g3 的等腰三角形因此在重绘图里被转了 60°，A 从顶点跑到右上角，用户对照原图会以为读错了。

几何量在旋转下不变，所以解完之后用 `align_to_pos()` 做一次 Kabsch 纯旋转（不许镜像），把图形摆回读到的朝向。若模型没给 `pos`，就跳过这一步，退回原来的行为。

### 5. 整句声明不翻译，正方形就退化成矩形

`四边形 ABCD 为正方形` 这句话在图上不画任何符号——正方形四边等、四角直，学生看一眼就知道，不必标。模型也就照着处理：把原句抄进 `given`，`marks` 里一个标记都不加。

于是求解器看到的只是「四个角都标了直角的四边形」，那是一个矩形。少了三边等，尺寸还浮着；CE 从「一个数」变成「随自由度乱跑的一段区间」——实测 1.379 ~ 19.95。

更麻烦的是这类漏读**没有任何报错**：残差是 0，图也建出来了，只是答案不唯一。所以 `relations.py` 必须把这些整句声明当成一等公民翻译：

```
四边形 ABCD 为正方形  →  四直角 + 三组邻边等
DE ∥ AC              →  一条平行
AE = AC              →  一条等长
```

翻完之后的每一条都能对回题面上的一句话，用户在步骤里看得见。

### 6. 证明题没有数值答案

`求证：CE = CF` 不是「求 CE 的长」。硬按求值处理，系统会去算 CE 到底多长，然后因为某个点还缺一维约束而报「条件不足」——题明明会做，报的却是「算不出来」。

现在 `parse_claim()` 先认结论，`Goal.kind = "prove"`，走另一条路：

1. **结论不能当条件**。模型经常把 `CE = CF` 也抄进 `given`。若照着建成约束，就是拿结论证明结论——什么都成立。所以解析出的结论等式要从约束里剔掉（`skip_equal`）。**角相等同理**：`求证：∠PAB = ∠PCB` 的写法和条件一模一样，只处理等长会在角相等题上照旧循环论证，所以 `build_constraints(p, scale, claim)` 要把结论显式传进去。
2. **验的是结论，不是数值**。解出图形后，在多组收敛解上分别量 CE 和 CF，全部相等（相对差 < 0.8%）才说成立。这一题 `CE = CF = 0.7321`，两组解一致。
3. **图形不唯一 ≠ 结论不成立**。如果每组的 CE 长度都不同，说明条件还留着自由度，但结论在每组上都对——这时如实说「结论成立，但图形本身不唯一，要严格演绎证明还得补条件」。

结论不成立时也不能含糊：直接说「与图形条件下不符」并给出数值差（`CE=0.7321，CD=1，相对差 26.8%`），提示多半是某条条件读错了。这一条同时能抓住「模型把已知条件读错」的情况。

### 7. 不给数字的条件，最容易被整个漏掉

有一类条件长这样：

```
∠PBA = ∠PDA
P 在平行四边形 ABCD 内部
```

它们的共同点是**一个数字都没有**——不给度数，不给长度，只给一个「相等」或一个「在哪」。于是在两处同时失守：

- `_seed`（演绎推理的事实库）只认 `∠ABC = 25°` 这种带度数的，角与角相等进不去；
- `build_constraints`（数值求解的约束）同样只认度数，这条约束根本没被建。

后果不是「少算了一点」，而是**题目被换成了另一道题**：那个本该被约束住的点成了自由点，优化器随便找个位置停下，结论于是「不成立」，报错还说「多半是某条已知条件读错或漏读了，请核对识别结果」。

**这就是错误归因最难查的地方**——系统把责任推给用户，用户照着重新拍一张，还是同样的结果。实测一道平行四边形题，加约束前 `∠PAB=147.99°、∠PCB=167.18°`，加之后两条都是 `92.38°`。

定位的线索在两处：

1. **看 `steps` 里的「条件：」那一行**。它列的是真正进了模型的约束。如果题面上明明有 `∠PBA = ∠PDA` 而这一行没有，就是这里漏了。
2. **看两个度数加起来是不是 180°**。`141.82° + 38.18° = 180°` 是个强信号：不是算错了，是那个点跑到形外去了，量到的是补角。所以「点在图形内部」这条也必须建成约束（`_inside_given` + 同侧判据），否则同一组条件在形外照样成立。

「在内部」写成软惩罚而不是硬等式：点在内部时它不该给求解增加任何约束力，只有跑出去才拉回来。


## 四、怎么判断"算不出来"

这是整套设计里最重要的一条：**条件不足时不硬给数**。

同一道题从 8 个不同随机起点各解一次：

- 目标值都收敛到同一个数（容差 1e-3） → 图形被唯一确定，给答案
- 收敛到不同的数 → 报「条件不足，答案不唯一」，并给出值域
- 残差压不下去 → 报「条件互相矛盾，找不到满足所有条件的图形」，提示某条条件读错了

对应到界面档位：

| 档位 | 条件 |
|---|---|
| 可以算（ok） | 解出来、唯一、没有冲突 |
| 需要你核对（review） | 有冲突，或解不唯一 |
| 算不出来（fail） | 残差压不下去，条件互相矛盾 |

置信度规则全写在 `pipeline.judge()` 里，不藏在别处。单源封顶 75%，和公式链路同一条规矩。

### 失败的时候说什么

这里有一个比技术更难的问题：解不出来的时候，界面该显示什么。

很长一段时间，答案是「把 `sol.steps` 倒出来」。那是写给开发者看的日志：

```
1. 读入 5 个点：A、B、C、D、P
2. 补全：题干称 A、B、C、D 构成平行四边形，已按两组对边平行建模
3. 条件：以 AB 作为长度基准；AB ∥ CD；BC ∥ AD
...
7. 不成立：∠PAB=147.99°，∠PCB=167.18°
8. 不成立：∠PAB=13.69°，∠PCB=174.46°
```

学生看完只知道「它没做出来」。更糟的是第 7、8 行——同一个结论连报几次「不成立」，还给出几组互相矛盾的数，除了让人怀疑系统，没有任何用处。

现在 `explain.diagnose()` 输出三段：**卡在哪 / 我读到的条件 / 先核对这三件事**。

它的价值在第 7 条坑上体现得最明显：诊断的第一条写的是「最容易丢的是只给相等、不给度数的条件」，而那道题真正的原因正是漏了 `∠PBA = ∠PDA`。系统第一次把用户指向了正确的地方。

失败时最需要的不是「它尽力了」，是**下一步该改什么**。

## 五、实测

四类不同题型，全部走真实 API、双通道：

| 题 | 题型 | 结果 | 档位 | 耗时 |
|---|---|---|---|---|
| g1 | 直角三角形 + 斜边中点 | CD = 5 | ok / 95% | 0.1s |
| g2 | 圆 + 直径 + 切线 | ∠P = 40° | ok / 95% | 0.8s |
| g3 | 等腰三角形 + 底角 | ∠A = 40° | ok / 95% | 16.8s |
| g4 | 直角三角形 + 勾股 | AB = 5 | ok / 95% | 17.3s |
| g5 | 正方形 + 平行 + 等长，**求证** CE=CF | 结论成立（CE=CF=0.7321，两组解一致） | ok / 95% | 21s |
| p1 | 平行四边形 + 内部点 + 两角相等，**求证** ∠PAB=∠PCB | 结论成立（92.38° = 92.38°） | ok / 75% | 0.8s |

g1/g2 命中缓存所以很快。g5 是最难的一题：条件一半在文字里（正方形、DE∥AC、AE=AC），目标是证明而不是求值，F 只是两条线的交点——上面三个坑全是它踩出来的。

p1 是用户反馈时贴的那道题，也是第 7 条坑的来源。它的置信度只有 75%，因为只有一路读图、没有旁证——这个数字是对的，不是缺陷。


## 六、能力边界

**能做**：三角形（中线、高、角平分线的点位关系）、直角与等长判定、圆（直径、切线、圆周角、圆心角、内接四边形、弦切角、切线长、垂径定理、相交弦、割线、切割线）、多边形的边长与角度计算、特殊四边形的整句声明、**全等与相似的判定及性质**、**求证两线段相等／两角相等／两直线垂直或平行／两个三角形全等或相似**，卡住时会**补一条真能走通的辅助线**（连接、作高、取中点、延长、作平行线、作角平分线、旋转、翻折）并明说。

关于证明题要说清楚：输出的是 **∵ ∴ 推理链**（每条结论挂着定理名），但它的**每一步都过数值验算**——规则触发靠结构，结论落地前在解出的图形上量一遍，对不上就整条丢弃。所以：

- 不是「模型写了一段读起来很顺的证明」，写错的步骤过不了验算这一关；
- 也不是形式化的自动定理证明——它没有符号证明器，不保证穷尽所有人能想到的路子，推不动就退回坐标法并如实说明；
- 写成论文时，可以说「带数值验算的前向链几何推理」，不宜说成 ATP。

**不做**：

- **需要连作两步的构造**（先作垂线再取中点、先旋转再连线）——候选是单步的，两步的组合会指数爆炸，暂不做
- **四点共圆的判定、托勒密定理、位似**
- **动点问题**（"点 P 在线段 AB 上运动，当 BP 为何值时……"）——这类要扫一遍点位再挑，属于另一套解法；含参的**方程**讨论已经做到了代数链路（见技术文档 M5）
- **立体几何**（三视图、空间关系）——题干命中的这类词会直接拒答并说明原因，不硬算

**已知的坑**：

- 学生不画标记时（该画直角的地方空着），系统只能报"存疑"，靠文字兜底
- 图形画得不准没关系（不看坐标量，只读标记），但**标记本身画错**就会跟着错
- 读图模型给小图时会漏整句条件，所以 `min_side=1100` 是硬性的，别为了省 token 调低
- 全等/相似的结论依赖两个三角形名的字母顺序（那是唯一的对应信息来源），读图把顺序抄反了会如实报「不成立」

## 七、怎么用

界面上第二个页签「几何题（题干 + 图形）」：

1. 上传照片，或点内置样例
2. 看结论：能算 / 需要核对 / 算不出来
3. **看重绘图**，和原图对照，确认点的位置和线有没有缺漏
4. 读错了就展开「识别结构」，直接改 JSON，点「按此结构重算」——不重新调 API，也不花钱

命令行：

```bash
python -c "from geoagent import pipeline; r=pipeline.run('fixtures/geo/g1.png'); print(r.solution.answer)"
```

投错页签也不会白跑：几何题传到「公式题」页签时，公式链路认出这是整页题、不自作主张地解析，而是**就地转给几何链路**，同一张图重读一遍，重绘图直接画在公式页签下面，结果也同步到几何页签。

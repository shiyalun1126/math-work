## 界面整页报「错误」：Radio 的 value 不在 choices 里（09:03）

**现象**：用户传了一张手写定积分 `∫₀² √(2x−x²) dx`，后端识别成功（"识别一致 100% · 4/4 候选语义一致 · 19.41s"），但界面上 badge/latex_box/preview/cands/steps **每个组件右上角都显示红色「错误」**，看起来像全线崩溃。

**日志给了确切原因**（Gradio 在 preprocess 阶段就抛了，函数体根本没执行）：
```
gradio.exceptions.Error: "Value: '\\int_{0}^{2} \\sqrt{2x - x^{2}} dx'
  is not in the list of choices:
  ['\\int_{0}^{2} \\sqrt{2x - x^{2}} \\, dx', '\\int_0^2 \\sqrt{2x - x^2} dx', ...]"
```

**根因**：`verify.cluster()` 里 `Cluster(latex=pe.normalized)` —— 簇代表存的是**规整后**的字符串（去掉 `\,`、压缩空格）。`cand_update()` 又拿 `verification.chosen` 当 Radio 的 `value`，但 choices 列的是**原始候选**字符串。规整版 ≠ 任何原始版 → Gradio 6 判值非法 → 抛 Error → 所有 outputs 一起标红。

**为什么以前没暴露**：夹具模式下 chosen 恰好等于候选原文；真实 API 下候选带 `\,` 之类噪声，一规整就永远对不上。属于"单测全绿、真实链路必崩"的典型。

**修复（双保险）**
1. `verify.py:104`：簇代表改用原始候选 `(c.latex or "").strip()` 而非 `pe.normalized`。规整只该存在于解析环节，不该流到界面。
2. `app.py:cand_update()`：加兜底——若 `chosen` 仍不在 choices 的值里，就把它作为「当前式」选项插到最前，`value` 必取 choices 内的值。**绝不能把不匹配的 value 传下去**，因为 Gradio 这一抛是整页级的，一个小组件能拖垮整个界面。

**新增 `tests/test_ui_contract.py`（3 条，全真 assert）**
- `chosen` 必须是某个原始候选（守聚类不改写原文）
- 正常路径 value ∈ choices
- 极端路径（塞入规整版）自动补选项且 value 仍合法

**结果**：`pytest` 8 passed（原 5 + 新 3）；服务已重启（旧 PID 21856 已停）。

**教训**：Gradio 的严格校验组件（Radio/Dropdown）当输入用时，value 不合法会在 preprocess 抛错，而它把错误广播到所有输出组件，很容易误判成"后端崩了"。凡是从后端字符串直接喂给这类组件的，都要在边界做"值必须属于选项集"的兜底。

## 几何题链路 geoagent/（09:16 起）

**背景**：用户问「如果上传几何题，有题目有图形那种呢」。先探测再动手，结论是能，但必须独立于公式链路。

**探测结论（`tools/probe_geo.py`）**：拿"题干+图形"整页图走现有提示词，模型把整段中文题干塞进 LaTeX（`1. 如图，在\triangle ABC中…`），下游必然解析失败。换成结构化 JSON 提示词后 4 次抽取 3 次成功（1 次 GLM 被截断）。

**架构**：新增 `geoagent/` 包，与 `mathagent/` 不共用中间表示。
- `schema.py` Problem/Mark/Circle，宽松解析 + `normative()` 规范化（点排序、线段端点有序、`["A","B"]`→`["AB"]`）
- `read.py` 双通道读图，`parse_json` 容忍 fence/前缀/截断（后撤逐次补括号）
- `crosscheck.py` 图文交叉校验，四级 ok/info/warn/conflict
- `solve.py` 坐标法 + Gauss-Newton + 回溯线搜索，多初值检测唯一性
- `render.py` 重绘（解出坐标就按真实坐标画，否则环形布局）
- `pipeline.py` 编排 + `judge()` 定档位

**关键决策**
1. **缓存 key 用提示词哈希**（`PROMPT_VERSION = "geo-" + sha256(PROMPT)[:8]`），根治上午那个"改了提示词缓存不失效"的坑。公式链路仍未改，靠手动清。
2. **文字补图形结构**（`enrich_from_text`）：模型常漏"点 C 在圆上"这种纯文字条件；"PC 是切线"也常被标成 ∠ACB（直径所对圆周角，对但不是切线条件）→ 补 `OC ⊥ CP`。
3. **防退化约束**：不加最小距离惩罚，优化器会把所有点缩到原点（叉积 0、到圆心距离全等、角度在零向量上兜底 1.0），得到 A=B=C 重合的假解——g2 实际踩到。
4. **目标只从「求…」里解析**：一开始从整段题干搜 `∠([A-Z])`，把已知条件 `∠C=90°` 当成"求∠C"，算出 53.13° 假答案。
5. **算不出就说不唯一**：8 个随机初值，目标值一致才给答案，不一致报「条件不足」并给值域；残差压不下报「条件互相矛盾」。

**智谱 max_tokens 硬上限 1024**（实测 1200 起报 400 code 1210），按通道给值 + 撞 400 自动降 1024。提示词要求紧凑 JSON。

**实测 4/4（全部双通道真实 API）**
| 题 | 题型 | 答案 | 档位 |
|---|---|---|---|
| g1 | 直角三角形+斜边中点 | CD = 5 | ok 95% |
| g2 | 圆+直径+切线 | ∠P = 40° | ok 95% |
| g3 | 等腰三角形+底角 | ∠A = 40° | ok 95% |
| g4 | 直角三角形+勾股 | AB = 5 | ok 95% |

**界面**：`app.py` 改成 `gr.Tabs()` 两个页签（公式题 / 几何题），密钥面板提到页签外共用。几何页签 = 原图上传 + 结论 + **重绘图** + 求解步骤 + 可编辑 JSON（改完「按此结构重算」，走 `pipeline.resolve` 不调 API，单源自动降 75%）。

**测试**：`tests/test_geo.py` 17 项离线全绿（含"条件不足要报不唯一"、"矛盾要报矛盾"、"点不能重合"）；全套 `pytest` 25 passed。

## 重绘图被用户指出"明显错了"——四处修复（上午）

用户传界面截图指出 g2 重绘图有问题（"那个是角P"）。核查后确认重绘图有四个真缺陷，答案 ∠P=40° 本身是对的：

1. **镜像**：重绘图 A/P 左右颠倒。根因是求解的规范固定（0 号点钉原点、1 号点压 x 轴）会把图形旋转，而数值解本身对镜像不敏感。
2. **直角标错位置**：模型把切点 C 的直角读成 `of=["AC","BC"]`（∠ACB），而原图画在半径与切线之间（∠OCP）。∠ACB 恰好也是 90°（直径所对圆周角），所以任何等式检验都发现不了——只有对着原图才看得出方框位置不对。
3. **P 悬空**：`segments` 里没有 B–P，P 只有一条切线连着，看着像认错了。
4. **目标角没标**：图上完全看不出在算 ∠P，用户以为系统在算 ∠C。

### 改法

| 文件 | 改动 |
|---|---|
| `schema.py` | `Problem.pos`：各点近似相对位置（0–100，y 向下），`_as_pos()` 兼容 dict/str/list 三种写法 |
| `read.py` | 提示词加 `pos` 字段（示例用 M/N/K，避免被照抄——第一版示例写 A/B/C，模型原样抄了回来）；明确"必须按实际位置重估" |
| `solve.py` | `seed_from_pos()` 当首起点；`align_to_pos()` Kabsch 纯旋转对齐；`repair_marks()` 切点直角归位；**`build_constraints` 加定标**（纯角度题钉住一条边，否则图形会缩成一团粉尘，残差卡 1e-3）；`_gauss_newton` 换成 LM 阻尼 |
| `render.py` | `_goal_mark()` 标红目标角/边（弧 + 度数，带描边）；`_extra_links()` 补画共线延长线；`render(..., goal=, value=)` |
| `pipeline.py` | `resolve()` 先 `enrich_from_text` 再 `repair_marks`（顺序反了切线找不到切点，标记改不动）；`goal_of()` |
| `app.py` | `_geo_outputs` 传 goal 给渲染 |

### 教训

- **"画对了结构"≠"画得看得懂"**：镜像、悬空点、未标注目标，都会让用户认为识别错了，哪怕数字全对。
- **提示词里的示例会被照抄**：示例坐标要用真实题目不会出现的字母（M/N/K），并写明"不要照抄"。
- **纯角度题缺定标**会让优化器塌缩；`distinct` 惩罚只能兜住"不重合"，兜不住"整体缩得很小"。
- **步骤顺序是接口**：`enrich_from_text → repair_marks → crosscheck → solve`，顺序错了不报错、只是悄悄不生效。

**测试**：`tests/test_geo.py` 23 项（新增 6 项：直角归位、无切线时不动标记、pos 朝向、对齐保距、延长线补连、目标记入解），全套 `pytest` 31 passed。

**补充（同日）**：`align_to_pos` 最终没用加权 Kabsch——几个估偏的点（g2 的 P 被估高 20）会把整张图带歪 10~15°。改成**旋转角只由主轴决定**（主轴 = 解出坐标里最长的那条线段，端点按 pos 方向对齐），其余点只用来判"往哪一侧翻"（允许镜像，因为度量量在镜像下不变）。四题主轴倾角与原图读数完全一致。全套 `pytest` 31 passed。

## 正方形证明题：重绘偏离 + 条件没编译 + 证明题当求值题（10:50）

**用户反馈**：上传「四边形 ABCD 为正方形，DE∥AC，AE=AC，AE 与 CD 相交于 F，求证 CE=CF」，重绘图里 A 在顶、B 右上、D 在底、E 在左，完全不是原图，问「这对么」。

**三个独立根因，一次性暴露**

1. **重绘退化成环形布局**。`render()` 只有「有 coords → 按坐标画」和「没 coords → 环形」两条路。8 个点排在圆周上就是用户看到的样子。而 coords 为空的原因是 `solve()` 只在「目标算出来了」时才存坐标——条件不足的题一张图都画不出来。**其实图建出来了（残差 2e-14），只是答案定不下来，这是两件事。**
2. **题干整句声明没进约束**。`四边形ABCD为正方形` 在图上不画任何符号，模型只抄进 `given`。于是求解器看到的只是「四角都是直角」的矩形，少了三边等，CE 在 1.379~19.95 之间乱跑。`DE∥AC`、`AE=AC` 同样只停在文字里。
3. **证明题被当成求值题**。`求证：CE=CF` 被 `parse_goal` 的兜底正则读成「求 CE 的长」，且 `CE=CF` 还留在 given 里当条件——拿结论证明结论。

**修法（新增 `geoagent/relations.py`）**

- 把题面整句翻成约束：正方形/矩形/菱形/平行四边形/正三角形 → 直角 + 边等 + 平行；`AB⊥CD`、`M是AB中点`、`AE与CD相交于F`、`F在AE上`。
- 从「线段连接 + pos」推断点落在哪条边上（`on_segment_lines`），容差 **1.05**。取 1.10 时把「F 在 AC 上」误判进来了（AF+FC 是 1.059 倍 AC），F 被钉在错的对角线上，算出 CE 与 CF 差 60%，反过来诬告条件矛盾。**误判比漏判贵得多**。
- 新增 `Derived.between`：`F 在 AE 上` 不只是共线，还要求 F 在 A、E **之间**。本题 E 恰好有两个解，一个 F 在线段内（CE=0.732）、一个在延长线上（CE=2.732），只写共线就报「不唯一」。加内点惩罚后 unique=True。
- `parse_claim()` + `Goal.kind="prove"`：结论从「求证/证明」后取；没有这两字但 `goal` 直接写成等式（`CE=CF`）也认；再退到题面末句、given 倒序。结论等式用 `skip_equal` 从约束里剔掉。
- 求解后 `verify_claim()` 在多组收敛解上量 CE、CF，全部相对差 < 0.8% 才说成立；图形不唯一但结论处处成立时，明说「结论成立（图形本身不唯一）」。
- 重绘三档：唯一解 → 真实坐标；有 pos → 按读到的位置（形状比例不作数）；都没有 → 环形。`describe_diff()` 把依据写在界面步骤末尾。
- 结论标签用 `_free_spot()` 在四周候选位里挑离所有线段最远的（原先写死在中点外侧，这题 CE/CF 都在右侧，标签必被 CF 竖线穿过）。

**读图侧的配套改动**

- 提示词加两条：`problem_text` 一字不漏照抄（「交于」「求证」最易漏）；点是交点时写「F 在 AE 上，也在 CD 上」，**不要**写「F 是 AC 与 DE 的交点」（实测四个字母错两个）。
- `prepare_image` 加 `min_side` 参数，几何链路用 **1100**（原来统一 640）。同一张 305px 截图，放大前 `goal` 读成「题干未写完」，放大后读成 `CE=CF`。
- `PROMPT_VERSION` 把预处理尺寸一起哈希进去——只哈希提示词的话，改 `min_side` 后旧缓存照样命中。

**踩到的实现坑**

- `between` 在两点重合时 `return [0.0]`（1 个），正常分支返回 2 个 → 雅可比行数随残差变 → `ValueError: shapes (35,) (34,)`。所有约束的短路分支必须返回**和正常分支同样多**的残差。
- 等长/平行去重时共用一个 `seen_pair` 会把 `AB=BC` 和 `AB∥BC` 互相吃掉，必须分开两个集合。
- `_find_point_on_line` 要支持「F 在 AE 上，也在 CD 上」——后半句不重复字母，得沿用上一个匹配到的点。

**验证**：g5 结论成立 CE=CF=0.7321（两组解一致，唯一，95%）；g1~g4 全部回归正确（CD=5 / ∠P=40° / ∠A=40° / AB=5）；`pytest` **38 passed**（新增 7 项）。

## 几何题投错页签：报「等号数量异常」（11:20）

**用户反馈**：把「四边形 ABCD 为正方形…求证 CE=CF」的照片传到了**公式题**页签，识别明明读对了整页文字，右下角却报 `ValueError: 等号数量异常：2 个`，配一句「识别出的式子无法转成语法树」。截图问怎么回事。

**根因**：不是识别错，是入口错。`parse()` 把整段题干（含两个 `=`）当算式切，切出 3 段 → 报「2 个等号」。界面把「投错了门」包装成了「解析失败」，用户只会去重拍。

**修法**

- 新增 `mathagent/route.py`：`detect()` 三分类 formula / geometry / prose。两段式判据：先看成句中文（CJK ≥ 6），再看几何特征词打分（求证 3、如图 3、四边形 3、∥ 3、正方形 2…）≥ 3。**必须先看中文**，否则 `\angle A+\angle B=180^\circ` 这种纯算式会被 ∠ 误伤。
- `latex.parse()` 开头就判入口，不是算式直接返回 `kind=geometry/prose` + 人话错误，不再往下切等号。
- `pipeline.run()`：新增 `_longest(cands)` 兜底——整页题在投票阶段常被全判「无法解析」，`chosen` 为空，只盯 chosen 永远发现不了投错门。命中时 `verdict="routed"`，求解一个字都不做。
- `types.PipelineResult` 加 `route / route_note / route_hints`。
- 界面：新增第 4 种徽章「routed」（蓝色，**不显示「一致度 0%」**——候选判废是因为「不是算式」，不是因为两路读得不一样）；`route_md()` 用 `plain()` 把 `\text{}` 还原成人话照抄出来，并说明「已就地转给几何链路」。
- **自动转链路**：`on_image()` 在 route=geometry 时拿同一张图再跑 `geoagent`，重绘图画在公式页签下方（`route_pic`，平时 `visible=False`），结果同步到几何页签。用户不用自己找页签重传。
- 反向误投也点了：`_geo_outputs()` 在 `points` 为空时提示「纯算式题请用公式题页签」。

**踩到的坑**

- `\text{...}` 会套娃（题干里有 `\text{ 与 }`），正则不能跨层匹配 → `plain()` 循环剥 6 次直到没变化。
- 原本想用 `gr.Tabs(selected=...)` 自动跳页签，但 `Tabs.postprocess` 是恒等函数，返回组件实例序列化不了；`gr.update` 能不能驱动页签切换到前端没法离线确认 → 放弃跳转，改成**就地画图**，行为确定。
- 公式页签的输出从 6 个变 12 个（+1 重绘图 +5 几何），`on_latex` 也得补齐 12 个，否则 click 绑定时报输出数量不符。

**验证**：`pytest` 44 passed（新增 `tests/test_route.py` 6 项）；用 `gradio_client` 打真实接口 `/on_image` 跑通，12 个输出齐全，蓝色卡片 + 重绘图可见 + 结论「CE = CF 成立 95%」。

## 求解过程改成学生能看的坐标法（14:35）

**用户反馈**：截图指出「求解过程」那栏是 12 条系统日志（读入 6 个点 / 补全 / 条件：以 AB 作为长度基准…残差 2e-14），要求「给解题过程，不是把题干条件罗列一遍，要学生能看懂、最详细」。

**根因**：`sol.steps` 从一开始就是给开发者排查用的，直接在界面上当「解题过程」渲染了。它记录系统做了什么，不解释这道题怎么做。

**做法**：新增 `geoagent/explain.py`，输出坐标法完整过程（建系 → 坐标 → 条件代回核对 → 公式代入 → 结论）。不调 LLM——编一段漂亮证明没人能验，坐标法每一步可当场验算。

**三个不显然的决定**

1. **基准边不能是要求的那条边**。原来 g4（AC=3、BC=4、∠C=90°，求 AB）把 AB 摆在 x 轴上再「求出 AB=5」，拿答案推答案。改成按 `(是否目标边, 是否已知长度, 是否挨着 A)` 打分选基准边 → 改用 AC=3 建系，B(3,4)，AB=√25=5 才是真算出来的。
2. **只平移+旋转，绝不缩放**：长度是题给的量，缩放后 `CD=5` 会变成 1。
3. **正方形压成一行**：四个直角 + 四条等边在条件表里占七行。判定要真找一圈首尾相接的四条边（正方形对角线也等长，只数条数会算错）。

**踩到的坑**

- `_rows` 里局部变量 `lens` 和函数级 `lens`（条件行列表）重名，导致 `out += lens` 拼进 4 个 float，`for cond, real in rows` 报 unpack 错。
- `\text{...}` 会套娃，`plain()` 得循环剥到不变为止（几何题那条早就踩过，这里又踩一次）。
- 坐标系 y 轴朝上朝下是随机的（解有镜像对称），得要「多数点在上半平面」那一版，否则学生看到 C 在 x 轴下方。
- 3 位小数要先圆再算，否则 `√24.999` 出不来 `√25`（(3.5999-5)²+(-4.8001)²）。

**界面**：`_geo_outputs` 主内容换成 explain 文本；老的 `sol.steps` 压成一行 `> 系统核对：读入 6 个点；补全 4 条…；残差 1e-15`。`geo_steps` 补上 `latex_delimiters`（否则 $$ 不渲染）。

**验证**：g1~g4 + 正方形证明题都出了完整解法（g1 建系 AC=6 → A(0,0) B(6,8) C(6,0) D(3,4) → CD=√25=5）；`pytest` **49 passed**（新增 `tests/test_geo_explain.py` 5 项）。

**边界**：证明题给的是坐标法验证，不是定理级演绎证明，写论文不能当自动定理证明。

## 解题过程从坐标法换成定理推理（17:10）

**用户三条批评**（针对上一轮的坐标法解法）：
1. 「你不知道他们都是多长，这都是你假设的」——`设 AB = 1` 是凭空塞进去的数字
2. 「你又怎么假设出来 E、F 的坐标」——E(0.366,1.366) 这种对中学生就是黑箱
3. 「几何题尽量还是用几何思维，谁平行，哪个角相等，用推理的形式」

第 3 条是方法论问题，不是文风问题。坐标法能算对，但解释不了「为什么」。

**做法**：新增 `geoagent/reason.py`，前向链推理引擎。
- 事实：`eqseg/eqang/angval/right/para/mid/coll/len`，每条带 pre（∵ 文字）和 deps（依赖 key）
- 规则 13 条：内错角、三角形内角和、角的分割、等量代换（角/边/长度三种）、等边对等角、等角对等边、等腰顶角↔底角、同射线角相等、勾股、斜边中线、正弦定理、直径圆周角、平角
- **验算是底线**：规则触发靠结构，结论落地前在解出的坐标上量一遍，对不上整条丢弃
- 输出：从目标回溯 deps，拓扑排序，只渲染这条链

**长度符号化**：无已知长度时把第一条边定为 a，坐标归一化，长度全写成 `a`/`√2a`/`a/2`，开头明写「a = AB，结论与 a 取多大无关」。

**坐标法退为兜底**（`force_coords=True` 可强制），g2 圆题仍走它。

**效果**：g5 正方形证明题 20 步纯几何推理（内错角 → 等腰 → 正弦定理 → 等角对等边）；g1 两步（勾股 + 斜边中线）；g4 一步。`pytest` 55 passed。

**踩的四个坑**
- `_ang(顶点, 点, 点)` 参数顺序错了七处，症状是「∠ACD 被当成 ∠CAD」，链全歪
- `kb.val("angval", 角)` 恒返回 None —— 事实存的是 `(角, 度数)`，拿角名当整个 args 查不到，得单写 `KB.angval()`
- `_r_median` 原来要求中点 D 在三角形里，但 D 在斜边 AB 上，A/B/D 共线构不成三角形 → 改成「先找直角顶点，再算 CD=AB/2」
- F 在 AE 上时图上只有 AE 一条线，但 EF 是 △CEF 的边 → `Ctx.reach()` 认「共线即相连」，否则最后一步凑不出三角形
- 同旁内角互补能推 ∠ADE=135，但学生看不到「哪个角等于哪个角」→ 删掉该规则，逼它走「内错角 + 角的分割」

**边界**：没有全等/相似判定、没有辅助线；正弦定理是高中内容，输出末尾注明「按初中要求可作垂线」。

## 22:05 补全全等/相似判定 + 辅助线（用户一句「补全」）

**背景**：上一轮收尾时列的未做项是「全等/相似三角形判定、辅助线、含参讨论、立体几何」。这一轮补前两项，第三项列为不做的边界，第四项改成明确拒答。

**全等（`cong`）**
- 判定：穷举两个三角形 6 种顶点对应，命中 SSS / SAS / ASA / AAS / HL 之一才产出事实
- 性质：`_r_cong_prop` 从 `cong` 反推对应边、对应角（`全等三角形的对应边/角相等`），这才是判定的用处
- **公共边**：△ABD 与 △ACD 共用 AD，这条不出现在 `eqseg` 里，却必须算（三线合一全靠它）。折中办法：公共边计入条件，但要求至少两条真条件，防止拿「AB=AB」凑出任何全等
- **索引坑**：`_tri_sides` 的第 k 条边是 v_k·v_(k+1)，正对 v_(k+2)（不是正对 v_k）。第一版按「正对第 k 个顶点」写，HL 把直角边当斜边，SAS 报成了 HL
- **规范写法**：`_canon_forms` 允许「整体轮换 + 整体翻转 + 两三角形对调」，不能简单排序字母（顺序即对应关系）；`_canon_sim` 对调时要取倒数

**相似（`sim`）**
- AA / SAS / SSS；数值兜底：三组对应边比值必须一致（差 < 2%）
- **相似比只能由已知长度算**（`lr`），不能拿量出来的坐标倒推，否则又退回坐标法；k 未知时只推对应角
- 有此得 BC=6（AD=2、AB=4、DE=3 → 相似比 0.5）

**同位角（`_r_corresponding`）**：`DE∥BC` 截出 △ADE 时 ∠ADE 与 ∠ABC 在截线同侧，是同位角不是内错角。早期只有内错角，AA 判定等于没有入口。坑：L1/L2 谁是谁决定「截线上哪个点在 X 外侧」，两个方向都得走，否则 ∠AED=∠ACB 那对漏掉

**辅助线（`_aux_lines` / `_aux_sets` / `prove(aux=True)`）**
- 只做「连接已有点」：新造的点没有坐标，结论验算不了
- 共线的两点不试；一条不通再试两条（0.04s/次，≤12 次）
- 走通才报，并在正文前写 `> **辅助线**：连接 AE、BF。`

**顺带的修复**：`relations.derive` 里「中点 ⇒ 落在该线段上」补成共线 + between。少了这条，D 是 BC 中点时凑不出 △ABD，推理被逼去「连辅助线 CD、BD」（一条没必要的线）

**立体几何**：`pipeline.solid_hints()` 命中正方体/棱锥/三视图/异面直线等词直接 fail 并说明「只解平面几何」，不再编一个二维的假答案

**效果**：正方形 SAS 全等 6 步；△ADE∽△ABC 3 步（两组同位角 + AA）；三线合一 3 步（公共边 SSS）；g5 仍是 20 步。`pytest` **63 passed**（新增 `tests/test_geo_cong.py` 8 条）。服务已重启（127.0.0.1:7860）

**仍不做**：含参讨论（属代数链路，需另设意图解析）、圆这一路的圆周角定理/切线长/弦切角、需要造新点的辅助线

## 16:40 补全圆定理 + 辅助线四种造法（用户「把圆和辅助线的相关内容知识也添加一下」）

**背景**：上一轮末尾列的「仍不做」还剩圆和造点辅助线。这一轮把两项都补上。

**圆（`reason.py`）**
- 新增事实：`center` / `on_circ`（点在圆上）/ `diam`（直径）/ `tang`（切线）。**以前 `_r_circle` 查 `diam` 却没人写 `diam`，那条规则是死代码**
- 同圆半径相等直接落成 `eqseg`——等腰 △OBC 全靠它，缺了连「∠OCB=∠OBC」都推不出来
- 七条定理：直径圆周角=90°、同弧圆周角相等、内接四边形对角互补、圆心角=2×圆周角、弦切角、切线长相等、垂径定理（直径⊥弦⇒平分弦）
- 「同弧/同侧」只能按解出坐标算叉积判；判错结论过不了验算，整条丢弃
- 圆心角只取画出来的那个（≤180°），优弧那种直接跳过，不写 250° 这种数
- **g2 从坐标法变成 6 步纯几何**：直径圆周角→内角和→平角→弦切角→等量代换→内角和，∠BPC=40°

**辅助线：从「只连两点」扩到四种造法**
- `Aux` 数据类：`desc / segs / pts / rels / rights / mids`
- **关键理由**：作垂线、取中点、延长造出来的新点，坐标是作图直接算出来的（投影 / 平均 / 两直线求交），所以和图上读到的点一样能验算——这是敢写进答案的前提
- 作垂线：`t ∈ (0.12, 0.88)` 才算（垂足贴端点等于没作）；造 `right` 事实
- 取中点：只给真三角形的边造，避免中点连出去拼不出东西
- 延长：交点须在至少一条边的延长线上，且 2.5 倍边长以内
- 排序：连线 → 作高 → 取中点 → 延长（越往后越不确定）
- 新点会改变共线关系，所以带点的辅助线强制重算 `between`

**顺带修掉的四个 bug（全是同一个家族：从名字反推顶点/直径）**
| 症状 | 根因 |
|---|---|
| 「∠A=25°」被记成 ∠ABC | `_seed` 写成 `_ang(arms[0], name, arms[1])`，顶点变成 arms[0] |
| 「求∠P」永远查不到 | `_find_goal` 同款写法；3 字母角名也用了 `_ang(name[0],…)` |
| 平角规则永不触发 | `_r_straight` 判据 `v in (x,a,b): continue` 把唯一正确情形（顶点=中间点）也挡了 |

### 一、变换型辅助线（`reason.py`，从 4 种扩到 8 种）

### 三、含参讨论（新文件 `mathagent/params.py`）

`discuss(lhs, rhs)`：主元优先 x → 按次数分情形（A=0 降次 / A≠0）→ 按判别式分情形（Δ>0/=0/<0）→ 每支找**见证**（一组真实参数取值，代回验证解成立）→ **找不到见证的分支删掉**。

- 见证的取值池 = 整数/半整数 ∪ 每个等式条件对每个参数的解。没有后半句，`mx²-3x+2=0` 的 Δ=0（只在 m=9/8）会被误判为不可能
- `Δ<0` 说「无实根」，不跟一次方程的「无解」混
- 二次项系数是单个字母时，把 A=0 代进后继条件与解里化简：「a=0 且 a-1≠0」→「a=0」
- 顺手修 `_solve_equation` 的未知数选择：原来取字母序最小的符号，`x²-2mx+m²-1=0` 被解成 `m=x±1`

## 结构改造：从「判题」到「判人」——批改链路 + 错题本

**起因**：用户觉得现阶段太鸡肋（只会解一道式子），要求最低做到「搜题 + 批改解题过程 + 错题分析解答」。讨论后确认：搜题其实已有（就是公式页签），真缺口是批改。

**核心判断**：批改不是新功能，是 J2 的完成形态——判定对象从「题」换成「学生写的那一版」。最值钱的场景是**伪推导**（过程错、答案对），作业帮和本 MVP 以前都会判「对」。

**新增**
- `mathagent/workcheck.py`：批改引擎。判据是**局部有效性**（相邻两式能否通过合法变换推出），不是全局相等——否则一题多解会被误伤。判定顺序：equiv → same_solution → lost(漏解) → gain(增根) → wrong。
- 硬约束：**判 wrong 必须给反例**（满足上一步却不满足这一步的取值），给不出就不判。`_counterexample()` 用上一步解集当探针。
- 说明行处理：能切出式子就切（"两边同乘2得 x=9"），切不出只展示。`declared` 与推断动作并列显示，**对不上不判错**（推断是启发式的，拿猜测否定学生等于另一种幻觉）。
- 结论矩阵：pass / partial(漏解) / **fake(伪推导)** / wrong / unknown / gap。
- 错因按**动作**归因不按题型：`d_B - d_A` 是常数 → 移项/变号错；`d_B / d_A` 是常数倍 → 漏乘漏除。
- `mathagent/cases.py`：错题本（data/cases.jsonl），按错因统计、复发检测（same_type）。
- `app.py`：新增「批改过程」「错题本」两个页签；公式页签更名「搜题 · 求解」。正确做法由 CAS 独立求解生成，不走 LLM。

**测试**：`tests/test_workcheck.py` 11 项；全量 **114 passed**。

**文档**：`docs/批改链路.md`（判据、反例义务、学生人话怎么处理、结论矩阵、错因表、已知边界）。

## 手写数据采集规格（回答"要我提供哪些数据、哪些题型"）

**核心判断**：要的是**两套目的完全不同**的数据，别混。
- **A 单行公式**：`shotlist.csv` 200 条 / 20 页已规划好（7 类题型：方程30、方程组10、化简25、求导积分25、复合结构30、难例30、自由写50），不用重设计题型，只差照片。支撑技术文档 §6 的识别类 8 指标与消融 A–E。
- **B 整页解题过程**：真正缺的。现有清单一条过程页都没有，而项目核心已是批改。按**错法**分组不按题型：正确(含一题多解/中文叙述)、**伪推导**、明显错、漏解、无法判定、拍摄退化、版式压力，共 20 页 / P0 最小 8 页。支撑结论准确率、冤枉率、伪推导召回、撤回正确率。
- **最小可答辩集 11 页** = A 的 page_13~15（30 条难例全 test）+ B 的 P0 8 页。

**关键事实（易错）**：test 105 条**散在 20 页里**，不是集中在 11 页。page_01~12 每页 8 train + 2~3 test，page_13~15 全 test，page_16~20 是自由写 50 条。所以"只拍 11 页 test"不成立，全拍反而更省事（挑页要重新对位）。

**最大的坑**：自由写 50 条的 `latex` 在 shotlist 里是空的，`init_labels.py` 生成 `labels.csv` 时直接跳过 → 照片拍了也没 ground truth。必须拍完看图补标。

**新增文件**
- `docs/手写数据采集清单.md`：给用户看的唯一入口（两套数据、题型表、页/split 分布、写拍命名规范、标注、命令、纸面 checklist）。
- `data/work_shotlist.csv`：20 页过程清单，`lines` 用 `|` 分行，含 `truth_grade/truth_first/truth_type` + **`baseline`（文字版引擎输出）**。真值按数学规范标，19 页逐条跑过 `grade()` 验证；W16~W18 故意 baseline=pass/fake 而 truth=unread，专测撤回。W20 一页两题标 `na`，只记录已知局限不进指标。
- `tools/check_capture.py`：拍完体检（缺页、HEIC 伪装、自由写真值、train/test 泄漏、清单字段自洽、`--split` 实切核对行数），只读，`--md` 出报告。
- `eval/run_photo_eval.py`：真实照片评测入口。`--collect` 调 VLM 写 `data/photo_results.jsonl`；默认读快照出 `reports/eval_photo_real.md`；`--smoke` 离线假结果写 `_smoke_` 前缀，**不污染正式报告**。指标沿用文本评测 + 撤回正确率 + 与 baseline 差异。

**顺手修的三件事**
1. `workcheck._relate` 崩溃：多元式子 `x²+y²=1` 让 `sympy.solve` 返回 `And`，`list(And)` 抛 TypeError 崩整页。方程组正是要拍的题型。加 `_as_sol_list`，算不出解集返回 `unknown` 跳过，**不顺势判学生错**；补回归测试。
2. **train/test 真泄漏**：`calc_016`(train) 与 `hard_027`(test) 同为 `\lim_{x \to 0} \frac{\sin x}{x}`。已把 hard_027 换成 `\lim_{n \to \infty} \frac{1}{n}`（考察点不变）。技术文档 §5.3 声称有 `check_data.py`，该脚本从来不存在，检查现落在 `check_capture.py`。
3. `work_shotlist.csv` W14 字段错位、`.gitignore` 补运行时产物、`docs/批改链路.md` 升 v0.4 补 §11.7 真实手写入口。

**验证**：全量 **148 passed**；文本评测数字不变；`check_capture.py` 报"未发现重复公式 / 清单自洽 / P0 缺 8 页"；`--smoke` 报告管线跑通；界面两条批改链路与启动自检通过。

**仍缺**：`data/inbox/` 照片 0 张；A 的 8 个识别指标入口还没接（等 `data/test/` 单行小图落盘）；U05 题面级不确定性缺口仍未修。采集是唯一串行关键路径。

## 公开数据集调研（回答"去网上找符合要求的数据集"）

**核心判断**：公开数据能顶 A（单行公式）和 B 的「切行/逐行识别」压力测试，**顶不掉 B 的核心**。硬条件三条：真实手写整页/多行图 + **逐行 LaTeX 转写** + 结论/首错/错因真值。单行公式集有①②没③；真实学生草稿集有①③**没②**；最接近的 ErrorRadar / OmniHandwritingOCR **目前下不到**。所以 P0 八页自采仍必须做，尤其伪推导 W05 与拍摄退化 W16/W17，公开数据一张都没有。

**可用六份（已核实）**
- **M²E**（魔搭 Wente47/M2E）：99,956 真实试卷多行公式块，`tex` 用 `\n` 分行 = 自带逐行 LaTeX，train/val/test 8:1:1，CC BY-NC 4.0。API 查到 7 文件：images.zip 543MB + train.jsonl 13.3MB + val/test 各 1.67MB。**需魔搭免费账号登录**（未登录 resolve 与 /repo?FilePath= 都报"当前操作需要登录"）。最适合压 `lines.py` 切行召回率。
- **HME100K**（74,502/24,607，K12 中文手写，最贴 A）/ **CROHME**（8,836 + 986/1147/1199，InkML 字段 `truth`）。许可最乱：官方 ai.100tal.com 需申请；Kaggle 镜像 744MB 自报 MIT；HF SoyVitou 99,109 行；**MaRDI/figshare DOI 10.6084/m9.figshare.30341779.v1 标 CC BY 4.0，建议用这个**。
- **MathWriting**（Google）：253,182 人写 + 396k 合成，InkML + normalizedLabel，CC BY-NC-SA 4.0（表达式另受 Wikipedia CC BY-SA 4.0）。官方 2.9GB 全量 / **1.5MB 摘录可匿名下**。已实测下载 1,620,634 B、5 目录各 100 条。**只有 9/24 条真值能被本项目 CAS 解析**——Wikipedia 高等数学公式，不是初中方程，只能测识别不能测求解。
- **ScratchMath**（AIED 2026）：1,720 张中国中小学生真实草稿图 + 7 类错因，CC BY-NC-SA 4.0，HF 两 parquet（22.7MB/89.7MB）hf-mirror 匿名可下。**无逐行 LaTeX**，且按"认知错因"分类与本项目"动作错因"不是一套，别硬映射。价值在真实涂改图可定性验证 `_apply_uncertainty`。
- **CASIA-HWDB** 2.0~2.2：52,230 中文手写文本行，2020 起学术免申请表、禁商用；补中文叙述行（"两边同乘2得"）。

**查到但拿不到（别写进方案）**：OmniHandwritingOCR（CIKM 2026，77,572 对、38,088 多行公式、**fact-based 标注保留学生原错**，与本项目原则一致）——官方 HF `gzn020619/OmniHandwritingOCR` **只有 README，明写 "Data release pending institutional review / No dataset files"**，论文 GitHub 404；ErrorRadar（ACL Findings 2026，2,500 题、错误步骤识别+分类）匿名仓库已不可达；EdLight（19K 专家标注）需 IRB+DUA，结课项目不现实。

**新增文件**
- `docs/公开数据集调研.md`：清单、许可、缺口、下载命令、导入脚本说明、**§6 可复现的核实记录**（含各 API 的 HTTP 状态与"需要登录"原文）、引用。
- `tools/import_public.py`：纯离线导入。`probe` / `mathwriting`（InkML→PNG + 与 `data/labels.csv` 同形 labels.csv，`--label-field truth` 兼容 CROHME，`--check-parse` 统计 CAS 可解析率）/ `m2e`（`blocks.jsonl` 保留 `tex_raw` + `lines.csv`，`has_align` 标 `\t` 竖式，去空格可选且有损）/ `scratchmath`（parquet→图+metadata，需 pyarrow）。每个输出带 `SOURCE.json` 记许可。
- `tests/test_import_public.py` 5 项离线测试；`.gitignore` 加 `data/public/`（体积大 + 多为非商业许可，不入库）；`docs/手写数据采集清单.md` 加 §7.1、`docs/批改链路.md` §9 补代码清单。

**验证**：全量 **153 passed**；导入链路真跑（MathWriting 摘录目录 24 张 + 直接吃 .tgz 9 张，渲染图为可读手写）；M²E 卡片样例切出 3/4 行；报告与采集体检数字不变。

**口径纪律**：公开数据单列「外部验证集」，指标与 `self_test` 分表，不写成"我们采集了 N 条"；多数为 CC BY-NC*，商用需换授权。下一步性价比最高：注册魔搭下 M²E，导 500~2000 块压切行召回率——不用等人动笔。

## 魔搭接入步骤 + M²E 切行评测入口补齐（22:40）

**用户请求**：「给我使用魔搭来帮助项目实现的步骤过程」。上一轮调研只到「注册魔搭下 M²E」，中间**缺下载脚本和评测入口**，所以这次把链路补成可照抄的 9 步。

**新增**
- `docs/魔搭接入步骤.md`：主交付。注册取 SDK 令牌（只走环境变量，不落盘/不贴对话）→ 装 modelscope → dry-run → 先下 18MB 标注验登录 → 再下 543MB 图包 → verify/unzip → import → 评测 → 报告口径 → 10 条排查 → 一页速查。含「能拿到/拿不到」表与可直接抄进论文的话术、不能写的四种说法。
- `tools/fetch_m2e.py`：封装官方 CLI（不自己写 LFS 下载）；默认 dry-run；`login` 失败自动退回 `download --token`（明文只进 argv 不打印）；`verify` 检查体积下限、jsonl 坏行、**Git LFS 指针**、zip 内图片数；`unzip` 按 basename 摊平并算与标注 `name` 的对齐率（<90% 要停）。

- `tests/test_m2e_pipeline.py` 9 项离线护栏（假 zip/LFS 指针、图片名对齐、指标计数、真实 split_page 连通、调参纪律、smoke 不覆盖正式报告）。

**同步**：`docs/公开数据集调研.md`（§3/§4/§5 指向新文档与脚本）、`docs/批改链路.md` §9 代码表、`docs/手写数据采集清单.md` §7.1、`.gitignore` 加 `reports/line_debug/`。

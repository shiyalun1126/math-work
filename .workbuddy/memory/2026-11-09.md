## 项目立项讨论：手写数学识别智能体（结课项目）

**用户诉求**：做一个能精准识别手写数学公式的智能体，几何图形作为拓展项。起点是先讨论方案。

**已达成的定位判断**
- 竞品（作业帮类）的瓶颈不是识别率，而是「题库检索优先」策略：原题不在库里就失效，答案与学生实际写的式子脱节，推导不可验证。
- 本项目差异化不在 OCR 准确率，而在**可验证性**：系统要能判断自己可能认错了，而不是硬猜。

**确定的五层架构**（识别 → 校验 → 求解闭环）
1. 输入：拍照 / 白板 / 平板笔迹
2. 感知层：VLM 识别为 LaTeX + 符号级置信度（基线 Qwen2.5-VL-7B 或 UniMERNet，LoRA/QLoRA 微调；不从零训 CAN/BTTR）
3. 结构层：LaTeX → 语法树（latex2sympy2），配语法约束解码（outlines / XGrammar）
4. 校验层（核心）：重渲染比对 + 多解投票（AST 语义等价，非字符串）+ 可解性检验；不一致则回问用户点选候选
5. 求解层：SymPy/CAS 计算，LLM 只负责讲解，禁止 LLM 算数

**关键设计结论**
- 优先在线笔迹（stroke）还是离线图像（拍照）需先定，前者数据效率高一个数量级但绑设备。
- 数据：CROHME / HME100K / MathWriting / IMG2LATEX-100K + 自采 200–500 张真实手写（纸纹、阴影、倾斜），自采数据是护城河。
- 评测四条线：ExpRate、语义等价率（AST）、人工干预率、端到端延迟。
- 主线实验：纯 VLM 端到端解题 vs 感知→形式化→CAS 闭环，对比答案正确率 / 幻觉率 / 人工干预率，可作论文骨架。
- 几何图形放拓展，路线为「图 → 点线圆约束的结构化 spec → 重绘制 → 与原图比对 → 迭代」，参考 FormalGeo、GeoQA、Geometry3K、AlphaGeometry；本质是形式化+求解器，不是 OCR。

**待用户确认**：课时与人力、算力（能否跑 7B QLoRA）、目标定位（demo / 完整研究 / 冲论文）、交付形态。

**下一步**：待确认后开始搭基线，先做「拍照 → LaTeX → 可编辑预览」的最小链路。

## 采集方案 v2：整页拍 + 自动切行

**起因**：用户指出上一版"四角必须入画"会推出"一页一题"的荒谬结论，指出浪费纸张。

**修正**：四角要求针对的是整张纸而非单题；采集改为三层——页层（整页拍）→ 行层（算法切）→ 样本层（单行图对应一个 id）。
一页 A4 写 10 行，200 条样本 = 20 张照片（原需 200 张）。

**产出文件**
- `docs/采集与切分方案.md`：完整技术文档（三层结构、采集规范、算法参数、实测、质检、失败模式、已知局限）
- `tools/split_page.py`：整页切行。Otsu 二值化 → 抹长横线 → 投影平方和最大化纠偏 → 水平投影找行带 → 高行带递归下刀。**输出灰度图而非二值图**（保留笔画粗细）
- `tools/route_crops.py`：按 manifest 行序 + pages.csv 映射到 shotlist id，再按 labels.csv 分流到 self/test，带 --dry-run 和行数校验
- `tools/selftest_split.py`：合成 A4 页自测（含粘连两行、横线本横线、1.2° 倾斜），实测 8/8 全对
- `tools/make_pages.py`：生成 pages.csv（20 页 × 10 行）
- `data/pages.csv`：页 ↔ id 段映射

**环境结论**：默认 `python` 是 3.13 且无法装包；**用 `F:/PyCharm/python.exe`（3.12，已装 numpy 2.5.3 / Pillow 12.3.0 / sympy 1.14.0）**。

**关键决策记录**
- 不做四角单应校正：纠偏 + 水平投影对 ≤3° 倾斜和轻微透视已足够，角点检测需要 opencv 或人工点选，收益不匹配成本
- 硬约束只有一条：上下两行墨迹不能接触（分母下探、上标粘连是主要破坏源）
- 行数校验是防错位的关键：切出行数 ≠ pages.csv 声明值则该页不进入后续流程

## 项目总技术文档

**文档中的关键判断**
- 置信度不用 logprob（VLM 多数不返回），改用 k=5 采样一致率，与多解投票复用同一套 AST 等价判定
- 重渲染比对不能用 SSIM（渲染字体与手写字体差异过大，无区分度），改用结构统计量：横向分块数、AST 深度、包围盒纵横比、3×3 墨迹密度相关性
- 算与讲分离：SymPy 出结果，LLM 只讲；LLM 每条等式断言都要重新解析并验算，不成立的剔除进 dropped_steps
- 测试集口径统一为 105 条（25 照抄 + 30 难例 + 50 自由写），指标附 bootstrap 95% CI
- 消融矩阵 A（纯 VLM 端到端）→ B（+形式化校验）→ C（+投票）→ D（+人工确认）→ E（换专用模型主干）

## 技术选型定稿：不训练，走云端双通道 + 本地兜底

**核心判断**：200–1500 条自采数据微调 3B 模型必然过拟合，效果不如「两个成熟模型跨源交叉验证」；而跨源投票恰好就是 M4 校验层要的东西，等于白拿一套投票机制。

**定案三件套**
- 主：SimpleTex 公式 API（专用，轻量 ¥0.04/次、标准 ¥0.05/次，累计赠 1000/500 次，支持手写）
- 副：Qwen3-VL-Flash（阿里云百炼，输入 ¥0.18/M、输出 ¥1.8/M，单次约 ¥0.0005，可放心 5 次采样）
- 底：PaddleOCR-VL 0.9B（Apache-2.0，BF16 约 2GB 显存，公式 CDM 91.43，断网可演示）
- 结构/求解/界面：latex2sympy2 + SymPy + Gradio（自定义 HTML 挂 MathLive）
- 微调仅在必要且有余力时做：百炼 LoRA 4B 训练 ¥0.006/千 token（1000 条 × 5 轮 ≈ ¥25）或本地 4060 QLoRA

**成本**：全项目 API 花费 < ¥50。**关键省钱动作：结果按图片 hash 落盘缓存**，改评测逻辑不重复付费。

**明确放弃**：从零训 CAN/BTTR、全参微调 7B+、Mathpix（贵）、LangChain/向量库（无检索需求）、Docker 微服务（现场多一个失败点）。

**机器**：RTX 4060 Laptop 8GB，torch/transformers/gradio/latex2sympy2 均未装，requirements.txt 已建。
**文档**：`docs/项目技术文档.md` §7 已重写为 7.1–7.7（结论/四候选对比/三件套理由/成本核算/其余各层/明确放弃/环境现状），§6.2 消融 E 行同步改为 SimpleTex。

## MVP 落地（可运行）

**成果**：`mathagent/` 五模块 + Gradio 界面跑通「图片 → LaTeX → 语义投票 → 求解 → 逐条验算」，7 个演示样例全过，2 例触发人工确认。

**模块与文件**
- `mathagent/perceive.py`：SimpleTex（header `token`，`/api/latex_ocr`，返回 res.latex/res.conf）+ Qwen3-VL（百炼 OpenAI 兼容端点，可采样 k 次）+ Fixture（演示夹具）
- `mathagent/latex.py`：归一化 + latex2sympy2 / sympy.parse_latex 双通道解析；失败返回 ok=False 不抛异常
- `mathagent/verify.py`：并查集聚类 + 语义等价（simplify(a-b)==0，3s 线程超时）+ verdict ok/review/failed + 差异片段提示（difflib）
- `mathagent/solve.py`：Step 带 check 三态（identity/equiv/none），事后逐条复算；二次方程出判别式；解代回验算；分母为零的增根剔除；积分结果再求导还原验证
- `mathagent/pipeline.py`：编排；「能解析但求不出解」自动降级 review；结果写 runs/
- `app.py`：Gradio 6.31，theme/css 走 launch() 而非 Blocks()；Markdown+latex_delimiters 渲染公式；候选点选即重算
- `demo.py` / `tests/test_smoke.py` / `tools/make_demo_images.py`

**踩过的坑（值得记）**
- Python re 里 `r"\left"` 是非法转义，必须 `re.escape(cmd)` 构造模式
- 归一化清理 `\ `（反斜杠+空格）会吃掉 LaTeX 换行符 `\\` 中的一个，需先把 `\\` 换成占位符保护
- 切分函数必须先判分隔符再走转义分支，否则 `\\` 永远匹配不到
- 步骤验算不能一律 `simplify(lhs-rhs)==0`：方程变形不是恒等式，要按解集比较（equiv）
- Gradio 6 的 `theme`/`css` 在 `launch()` 参数里，`Blocks()` 不接受
- Ink Free 缺 ∫/²/ˣ 字形会出豆腐块，演示图改用 `STKAITI.TTF`（楷体，符号齐全）
- 首屏不要依赖 `demo.load` 异步渲染，直接在组件 `value=` 里预计算，避免截图/首屏空白

**运行**：`F:/PyCharm/python.exe app.py`（7860）；`python demo.py` 跑全部样例；`MVP_PORT`/`MVP_DEFAULT_IMG` 环境变量可切端口与默认样例。无密钥自动走 fixtures 演示模式。
**截图**：`docs/mvp_ui.png`（一致态）、`docs/mvp_review.png`（歧义追问态）。
**文档**：`docs/MVP说明.md`。

## 首把真实密钥接入与一轮修正（20:30）

用户只加了 `DASHSCOPE_API_KEY`（SimpleTex 仍空）。实测暴露四个问题，均已修：

1. **模型名不存在**：`qwen3-vl-flash` 在该账号不存在。`GET /compatible-mode/v1/models` 显示只有 `qwen-vl-ocr`、`qwen-vl-ocr-2025-11-20`、`qwen3-vl-plus`。
   → 默认改 `qwen3-vl-plus`；新增 `perceive.list_vl_models()`，模型名错时报错里直接列出可用清单；`check_env.py --models`
   → `qwen-vl-ocr` 需专门 task 指令，通用提示词返回 `NOMATH`，不能当主力
2. **单源自证被当成 100%**：同模型采样 2 次一致→界面显示「可放心求解」。→ `verify` 按厂商判独立性（`_vendor`），单源时置信度上限 0.8，卡片加「单源·无旁证」标签
3. **多行方程组解析失败**：模型输出 `x + y = 3 \\ x - y = 1`（无 cases 环境）。→ `latex._as_system()` 自动包 cases；防误伤：仅"每行含等号且行内无逗号、2–6 行"才包
4. **行数检测误报**：固定阈值 165 与 Otsu 都把"纸外桌面 / 横线本淡线"当墨迹，一行公式数成 3 行。→ 改局部对比度（与高斯模糊背景比较，暗 28 以上才算墨迹），四张模拟照片均归 1 行
5. **讲评误伤**：`(x-2)(x-3)=0` 属合法改写却被拦。→ 正则先抠算式片段 `_math_part`；新增 `_same_equation`（差非零常数倍即视为同解）

**其它**：`tools/make_photo_sample.py`（透视/侧光/噪点/模糊模拟，4 档）；`demo.py --offline` + `pipeline.run(force_fixture=)`；`app.py` 加静态占位（等待识别/步骤说明）与 `MVP_AUTORUN` 截图开关；`tests/test_explain.py`（10 断言）。

**坑**：中易楷体 `simkai.ttf` 没有 `²` 字形，渲染成空方框，模型只能猜。必须用 `STKAITI.TTF`（华文楷体）。
**实测**：3 套测试全绿；7 例演示（真实 API）全过；4 张模拟照片识别全对；单源 80%。
**追加**：讲评提示词禁止引用具体数字（"和为一次项系数的相反数"替代"和为5"）。起因是实测发现模型把 x²-5x+6 的"和为 −5"说成"和为 5"，回扫抓不住这类文字口误，只能从源头限制。

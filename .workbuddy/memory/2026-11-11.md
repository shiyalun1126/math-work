## 用户点头：接含参数方程 + 答案缓存（10:0x~10:2x），API 可随便用

**含参接入**（`mathagent/equations.py`）
- `classify()` 重写"多符号"分支：只有一个 `x/y/z` 时它是主元，其余符号按**参数**看
  （中学「关于 x 的方程，a 是参数」的写法）；`x²+y²=1` 不走这条（x、y 都在 → 仍是
  `nonlinear` out）。判出参数 → `kind="param"`, coverage=`edge`。
- 答案不再压成一句：`Answer.branches` 存 `params.discuss()` 的分支（按 `\quad ①` 拆），
  界面上**一支一行**。这是有意的——压成一行最容易漏看的正是被压掉的那一支。
- 解里带参数但不必分情形（`x²-2mx+m²-1=0` → `x=m±1`）时，`_fix_param_note()` 把
  徽章口径改成"不需要分情形"，不写空话。**缓存命中也走这一步**（缓存存答案不存这句话）。
- `_checks()` 顺手修：代回验算的主元优先取 `x/y/z`，否则 `x²-2ax+a²` 会拿 `a` 当未知数验；
  `sr.kind=="param"` 直接跳过（discuss 已用见证值验过每一支）。

**答案缓存**（`_ANSWER_CACHE = Cache(subdir="equation_answer")`）
- 键 `(CACHE_VERSION, pe.sympy_str, "explain"|"plain")`：用**标准形**而非题面文字，
  `x^2-5x+6=0` 与 `x^{2} - 5x + 6 = 0` 命中同一份；讲评是否生成也进键。
- **只缓存算成功的**，`x^4-1=0` 这类出范围的绝不写盘——否则判据修好了还会拿到旧"不给"。
- 版本号 `CACHE_VERSION="eq-answer-v1"`，改判据必须升，避免旧算法结论顶替新结果。
- 命中时 `Answer.cached=True`，界面明写"命中答案缓存，没有重新算，也没花钱"。

**实测**：`ax=2` → 2 支；`(a-1)x=1` → 2 支；`mx^2+2x+1=0` → 4 支（Δ>0/Δ=0/Δ<0/m=0）；
`x^2-2mx+m^2-1=0` → `x=m-1，x=m+1` 且标"不需要分情形"；同一题换写法第二次 `cached=True`。

### 傍晚：方程组批改原来根本不通，已修（方程题型补完最后一块）

**用户问**："有没有一个页面，能不能进行一个简单方程组的测试" → 查下来：搜答案能，**批改不能**。

**缺陷**：`workcheck.grade()` 是单方程递推模型，"每一步和上一步比"。方程组里前两行是
**并列的题给条件**，`x-y=1` 接在 `x+y=5` 后面必然"对不上上一步"，于是一份完全正确的
二元一次方程组解答被判 `wrong`，而且从第 2 步开始后面全部连锁判错。
更隐蔽的是 `_diffof()` 对多方程是**把所有等式相加**（`x+y=5` + `x-y=1` → `2x-6`），
y 直接被消掉，等于方程组在这条链路上根本没有表示。

**修法**：新增 `_grade_linear_system()`，把"递推链"换成"条件集 + 联立"。
维护 `facts`，每多一行就 `linsolve(facts + new)` 一次，看解集怎么变：
- 没变 → ✓（区分"照抄题面"与"消元/移项"，`_pair_same` 判是否本来就在 facts 里）
- 变小且非空、还在开头 → ✓ 题给条件；进了推导区 → ✗ 丢解
- 空集 → ✗ 不成立

入口 `_looks_like_system()`：两个未知数以上且全为一次。一元二次不进来（相邻两步就是等价变形）。
`linsolve` 返回的是 `sympy.Tuple`，不是 Python tuple，必须走 `_row_of()` 才能解包——
这里踩过一次 `AttributeError: 'Tuple' object has no attribute 'expand'`。

**两个配套修正**：
1. 题面标记（`role="problem"`）原来是"同解就算题面"，题面给 `x+y=5, x-y=1` 时会把学生的
   推导 `2x=6` 标成题面，那一步就永远不参与判定。改成三级匹配：字面归一 → 逐条等式能对上
   题面里的某一条（`_pair_same`）→ 才退到同解集。
2. 答案核验必须用**原题条件**，不能用被 assign 扩充过的 facts，否则学生自己写的答案代回去当然成立。

**边界**：题面本身矛盾（`x+y=1` 与 `x+y=3`）判 `gap`，不给对错——学生没错，是题抄错了。

**实测（页面同款调用链路）**：
| 情形 | 结论 |
|---|---|
| 正确过程（含贴/不贴题面） | pass |
| 第二步抄错号（题面给了） | wrong，first_error=2 |
| 只解出 x 没解出 y | partial |
| 答案代回不成立 | wrong |
| 过程错但答案对 | fake |
| 三元方程组 | pass |
| 题面自身矛盾 | gap |

### 晚：结果卡去工程语言（面向中小学生）

**用户问**："这是过程还是日志？面向中小学生他们看得明白不" → 是结果卡，但有 4 处说机器话。

**逐条**：
1. 步骤标题 `1.方程 2.方程 3.解得 4.代回验证` 是 CAS 内部记账：两个"方程"看不出是题给的两个条件，
   "解得"把唯一的教学重点（消元）吃掉了。
2. `4.代回验证 0 = 0, 0 = 0` 最糟——残差只有写程序的人认得，学生看到只会困惑。
3. "公式与答案全部来自 CAS 验算"：中学生不知道 CAS。
4. "耗时 solve 0.00s / total 1.96s"：运维日志。

**改法**：`equations._system_steps()` 按"看条件 → 消元 → 解出一个 → 回代 → 检查"重写，
三条路线按学生的自然选择排序：
- 某项系数相同/相反 → **加减消元**（最省事，优先）
- 否则有 ±1 系数 → **代入法**
- 都不行 → **倍乘消元**（①式×3 − ②式×2）
挑不出干净路线就返回空，退回通用步骤，不硬编。

**踩过的坑**：
- 最初把代入法排在加减前面，讲评说"相加最快"、步骤却去代入，自相矛盾 → 改成能直接抵消时先加减。
- `5y - 10 = 0` 是机器写法，学生写 `5y = 10` → `_lin_show()` 把常数移右边。
- `2 + 1·y = 3` → 直接 `to_latex(expand(oa*val + ob*other))` 得 `y + 2 = 3`。
- 缓存键含 steps，改步骤要 bump `CACHE_VERSION`（v1→v2）或清 `.cache/equation_answer/`，
  否则改完看着没生效（浪费了一轮排查）。
- `__pycache__` 之外还有答案缓存，两个都要清。

**页面层**：`_steps_md` "### 步骤"→"### 怎么做"；讲评注脚去掉 CAS；`_meta_md` 删掉耗时，
识别可信度改写"照片识别可信度 92%，建议对一下方程"。全量 **231 passed**。

### 用户核对 x²-5x+6=0 这一题：判对了，但判错理由指错了方向

**用户**："我确实写错了，你现在使用的是哪个大模型" → 结论没错，理由错了三处。

**数学事实**：`x²-5x+6=(x-2)(x-3)`，根 2、3；学生写 `(x+1)(x-6)` 乘开是 `x²-5x-6`，
常数项 -6 ≠ +6，两个根 -1、6 也是错的。判 wrong 正确。

**缺陷（全部是"结论对、说明错"，比判错更难被发现）**
1. **错因说成"移项/变号错"**。这一步根本不是移项，是因式分解。原 `_wrong_type` 只看
   `d2-d1` 是不是常数（这里是 12），就归类成移项变号；`_errtype` 又按 `"常数" in wtype`
   映射。学生照着"移项"去查，查十遍也发现不了问题。
   新增 `_factor_diag()`：`_is_factored()` 判 cur 是否为 Mul 且含 Add 因子，
   再逐项比对 `Poly.all_coeffs()`，直接说"常数项对不上：乘开是 -6，原式是 6"，
   并给出 `(x-2)(x-3)=0`（根为有理数时才算，避免瞎给）。
   `_errtype` 里 **"因式分解"必须排在"常数"前面**——新描述里含"常数项"三字，
   先命中"常数"又会被映射回移项变号。
2. **反例是机器话**："取 x=2：上一步两边相减为 0，这一步却是 -12≠0"。
   "两边相减"是把等式搬成 f(x)=0 的机器动作，学生没这么算过。改成
   "把 x=2 代进去：上一步成立；这一步左边 = -12，右边 = 0，不相等"（`_side_val`）。
3. **"读不出" 和 "你写的" 自相矛盾**：`x=-1  x=6`（空格隔开，没写"或"）整行 unparsed，
   表格判"读不出"，结论却说"你写的：x=-1、x=6"。新增 `_split_assigns()`：
   整个字符串正好由几个"字母=数"拼成时才切，中间只许空格/逗号；
   `x=2y` 这类**不许切**（会凭空造出 `x=2` 这种学生没写的答案）。

**踩坑**：`_counterexample` 用了 `to_latex` 但 `workcheck.py` 只 import 了 `parse`，
`NameError` 直接崩在 grading 里——改函数先看模块已经 import 了什么。

**测试**：231 passed（这轮没新增用例，待补因式分解错因、空格多解两项）。
**未修**：截图底部"切出来的每一行"画廊把宽行图按 cover 裁成方块，只剩中段笔画放大，
看着像乱码；需 `object_fit="contain"` 或按 4:1 补白。
